# 工业设备通讯三阶段修复实施计划

**目标：** 将现有 AIM 通讯和独立边缘网关修复为可审计、可补传、可扩展的通讯闭环，并逐步支持标准事件、命令回控及协议插件。

**架构：** 第一阶段保持现有 MES/AIM 兼容，所有事件进入可靠本地 outbox，HTTPS 是默认闭环传输，MQTT 在中央消费者完成前禁止生产启用。第二阶段增加标准事件业务消费者、命令队列和边缘 ACK。第三阶段将设备驱动统一到隔离插件进程和协议注册表，按设备类型扩展，不让驱动直接访问 MES 数据库。

**技术栈：** Python 3.8、Flask、SQLite（现有部署）、pytest；后续插件通过独立 Python worker 和标准 JSON 事件/命令契约通信。

## 全局约束

- 不删除或清理现有工单、报工、设备和测试数据。
- 每个行为变更先写一个能失败的测试，再修改生产代码。
- 保持现有 AIM V1/V2 设备协议兼容；V1 只允许明确配置来源 IP。
- MQTT 在中央消费者上线前不得把 Broker PUBACK 当作 MES 入库确认。
- 所有边缘事件必须可重试、可观测、可人工重放。

## 阶段一：可靠通讯闭环

1. 为 AIM 事件桥接、MQTT 门禁、死信重放、V2 nonce/时间窗、sequence 冲突和设备生命周期新增失败测试。
2. 将 AIM outbox 与边缘事件存储统一，增加后台 dispatch、重试退避、人工重放 API；死信不再自动永久丢失。
3. 为 V2 请求增加 timestamp/nonce 校验和已用 nonce 表，响应携带可校验的 request token；旧协议仍可配置兼容模式。
4. 标准事件按设备生命周期（boot_id）排序，事件 ID 内容冲突和 sequence 冲突进入隔离状态，不再静默 accepted。
5. MQTT 传输在中央消费者未注册时启动失败，并增加消费者确认协议；HTTPS 作为默认生产传输。

## 阶段二：业务与命令闭环

1. 新增事件处理表、处理租约、处理状态和失败重试，按事件类型调用生产、质量、设备状态服务。
2. 新增命令表、幂等键、权限/工厂范围、过期处理、边缘租约和 command.acknowledged/failed 回写。
3. 新增边缘离线快照（有效工单、路线、模板、准入规则）及版本校验，中央恢复后自动补传并对账。
4. 增加管理端事件积压、死信、命令状态和离线快照健康度页面。

## 阶段三：协议插件与容量

1. 定义 driver registry、插件 manifest、权限声明、配置校验、健康检查和隔离 worker 接口。
2. 将 AIM、海康 TCP、CSV 迁移为首批插件，并加入 TCP、串口、USB HID、Modbus TCP/RTU 适配器。
3. 增加 OPC UA、S7、MQTT、HTTP/Webhook、SMB/SFTP 适配器的接口与模拟器；私有协议通过 SDK 接入。
4. 用 worker 分片替代每端点一个进程，增加 1000 台设备、72 小时运行、7 天断网恢复和恢复演练测试。

## 验证

- 阶段一：通讯专项测试全部通过，并验证 Broker 可用但无消费者时不会确认出队。
- 阶段二：事件从设备入站到生产业务、命令到设备 ACK 全链路测试通过。
- 阶段三：模拟 10 个工厂、1000 台设备连续运行 72 小时，断网 7 天后数据无丢失并可对账。
