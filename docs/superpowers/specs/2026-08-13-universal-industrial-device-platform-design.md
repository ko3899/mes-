# 通用工业设备接入平台设计

## 1. 产品定位

本项目从单一 AIM 机台通讯能力升级为可对外销售和合作交付的通用工业设备接入平台。平台面向约 10 个工厂、合计约 1000 台设备的首个规模目标，同时允许按客户实际规模横向扩展。

第一阶段采用客户本地私有化部署。每个客户拥有独立的中央服务、数据库、消息服务、边缘网关、文件归档和授权，不与其他客户共享运行环境或数据。平台支持合作伙伴白标交付，可替换品牌名称、Logo、域名、主题、登录页和版权信息。

默认商业交付内容为私有化安装包、部署文档、运维文档、接口文档、设备模板及协议插件 SDK，不交付核心源码。源码授权只面向单独签署源码授权合同的合作伙伴。

“通用”指平台内置市面主流公开协议，并通过稳定的插件 SDK 接入厂家私有协议。对于未公开协议且没有 SDK 的设备，必须由厂家或客户提供协议资料，平台不承诺无资料自动兼容。

## 2. 目标与非目标

### 2.1 目标

1. 支持扫码枪、扫描头、PLC、CNC、视觉检测设备、机器人、仪表、测试机和文件型设备等常见设备类别。
2. 统一接入串口、USB HID、TCP/UDP、HTTP/WebSocket、MQTT、OPC UA、Modbus TCP/RTU、Siemens S7、EtherNet/IP、SMB/SFTP 和数据库交换。
3. 将所有厂家协议转换成稳定的 MES 标准事件，避免生产业务直接依赖某个品牌或协议。
4. 支持 10 个工厂、1000 台设备，单厂约 100 台设备的初始目标规模。
5. 工厂与总部断网时可继续执行本地生产准入、采集、缓存和必要指令，联网后自动幂等补传。
6. 支持每厂双边缘网关主备、中央服务高可用、配置分批发布和失败回滚。
7. 支持私有化离线安装、离线升级、备份恢复、白标品牌和软件授权。
8. 向合作伙伴开放协议插件 SDK、设备模板导入导出、模拟器和录包回放能力。

### 2.2 非目标

1. 平台不替代 PLC 安全程序、急停、安全光栅、运动控制和机械联锁。
2. 第一阶段不承诺覆盖所有厂家私有协议；私有协议按插件逐项适配。
3. 第一阶段不建设公共云多租户 SaaS；客户之间采用物理或部署实例隔离。
4. 边缘断网运行不代表所有中央 MES 功能离线可用，只保证已下发规则范围内的生产准入和设备事件闭环。
5. 第一阶段不直接建设预测性维护模型，只保留标准数据和模型下发接口。

## 3. 总体架构

采用“现场设备层 → 工厂边缘网关集群 → 中央设备接入平台 → MES 业务核心”的四层结构。

### 3.1 现场设备层

设备通过自身支持的以太网、串口、USB、现场总线、文件目录或数据库接口连接本厂边缘网关。老旧明文协议只允许存在于隔离的 OT 设备网络，不允许设备直接跨广域网访问中央 MES。

### 3.2 工厂边缘网关集群

每个工厂部署两台边缘网关，形成主备。网关职责包括：

- 加载和隔离运行协议插件。
- 维护设备连接、心跳、采集和指令会话。
- 执行已下发的工单、SN、工艺和质量准入规则。
- 将原始数据规范化为标准事件。
- 使用本地数据库保存至少 7 天事件和必要业务快照。
- 总部断网期间继续运行，恢复后按顺序补传。
- 提供本地诊断、原始报文、插件日志和设备模拟能力。

双网关通过设备租约确定采集所有权。同一设备任一时刻只能被一个活动网关采集和控制。活动网关失联且租约到期后，备用网关接管；旧网关恢复时必须重新竞争租约，不能直接恢复写入。

### 3.3 中央设备接入平台

中央平台负责客户实例内的工厂、车间、产线、网关、设备、驱动、模板和配置版本管理；接收网关消息、路由 MES 指令、维护设备数字状态、执行配置发布、汇总监控告警并保留审计。

中央实时通讯使用支持集群的 MQTT 服务，管理和低频调用使用 HTTPS API。中央业务和设备元数据使用 PostgreSQL，原始 CSV、图片、波形和检测文件存入客户内部对象存储或受控文件归档。

### 3.4 MES 业务核心

MES 不再读取具体协议报文。它只消费扫码、状态、参数、报警、产量、质量、能耗和命令结果等标准事件，并发布生产准入、模板下发、参数设置和任务控制等标准命令。

现有 AIM 通讯被迁移为第一个正式协议插件，而不是继续作为 MES 内部特例。

## 4. 部署与商业交付

### 4.1 私有化部署

每个客户部署独立的：

- MES 与中央设备平台服务。
- PostgreSQL 数据库。
- MQTT 服务。
- 文件或对象归档服务。
- 监控、日志和备份组件。
- 各工厂双边缘网关。

中央平台支持 Linux/Windows 服务器，并优先提供 Docker Compose 离线部署包。边缘网关支持 Windows 和 Linux，根据设备驱动、串口板卡或厂家 SDK 的操作系统限制选择安装环境。

### 4.2 白标能力

品牌配置存放在客户或合作伙伴发行配置中，不复制代码分支。可配置项包括系统名称、Logo、主题色、登录页、域名、帮助入口、版权主体和技术支持信息。核心升级包对所有品牌共用。

### 4.3 授权策略

签名授权文件至少包含客户标识、合作伙伴标识、部署实例、工厂上限、网关上限、设备上限、模块范围、有效期和宽限期。授权校验失败不得立即停止现场生产；已授权设备在宽限期内继续运行并产生告警，新增设备和管理变更受限。

授权验证不能成为设备实时通讯或断网生产的在线依赖。客户无公网时可使用离线申请文件和离线授权文件完成激活。

## 5. 协议插件体系

### 5.1 插件分类

插件按扫码、PLC、机床、视觉检测、机器人、仪表、文件和数据库八类组织。首批内置适配器覆盖：

- TCP 客户端与服务端、UDP。
- RS-232/RS-485 串口、USB HID 扫码枪。
- HTTP 客户端、Webhook、WebSocket。
- MQTT 3.1.1/5.0。
- OPC UA 客户端。
- Modbus TCP/RTU。
- Siemens S7。
- EtherNet/IP。
- SMB、SFTP、目录文件采集。
- PostgreSQL、MySQL、SQL Server 等数据库轮询或增量交换。

厂家私有协议通过 SDK 插件接入。Python SDK 为首个正式 SDK，后续根据合作伙伴需求增加 .NET 和 Java SDK。

### 5.2 插件边界

每个插件在独立工作进程运行，不能直接访问 MES 数据库。插件通过网关 SDK 获得有限能力：读取自身配置、建立授权范围内的设备连接、提交原始帧和标准事件、接收标准命令、写入自身状态和日志。

插件包包含签名清单、插件 ID、版本、支持平台、配置模式、权限声明、入口点和兼容的网关版本。安装前验证签名和兼容性；升级保留上一版本，并可一键回滚。

### 5.3 统一驱动接口

驱动生命周期至少包含：安装校验、配置校验、连接、健康检查、读取、订阅、写入、命令确认、断线重连、停止和诊断。驱动异常只能影响其负责的设备，不能终止网关主进程或其他插件。

插件 SDK 提供设备模拟器、报文录制、脱敏导出和确定性回放，使合作伙伴在没有真实机台时也能开发和回归测试。

## 6. 标准事件与命令

### 6.1 标准事件包络

所有设备事件采用统一包络：

```json
{
  "schema_version": "1.0",
  "event_id": "01K2H9VJQF01AIM02800000129",
  "customer_code": "CUSTOMER-A",
  "factory_code": "F01",
  "gateway_code": "GW-F01-A",
  "device_code": "AIM-028",
  "event_type": "quality.completed",
  "occurred_at": "2026-08-13T10:30:18.235+08:00",
  "received_at": "2026-08-13T10:30:18.412+08:00",
  "sequence": 129,
  "correlation_id": "REQ-20260813-000129",
  "payload": {
    "workorder_no": "WO20260813001",
    "sn": "SN20260813000028",
    "result": "NG",
    "measurements": {"width": 12.52, "height": 8.31}
  },
  "raw_reference": "archive/2026/08/13/report028.csv"
}
```

`event_id` 全局唯一，`sequence` 在同一设备身份和设备生命周期内单调递增，`correlation_id` 关联准入、加工、检测、报告和 MES 命令。中央平台按 `event_id` 幂等接收，并按设备序列检查缺口和乱序。

首批标准事件包括：

- `barcode.scanned`
- `device.connected`、`device.disconnected`、`device.state.changed`
- `production.started`、`production.completed`
- `quality.completed`
- `measurement.sampled`
- `alarm.raised`、`alarm.cleared`
- `count.changed`
- `energy.sampled`
- `command.acknowledged`、`command.failed`

### 6.2 标准命令

命令包含命令 ID、目标设备、命令类型、参数、配置版本、创建时间、有效截止时间和幂等键。设备或插件必须回传已接收、执行中、成功、失败或过期状态。

过期命令不得在断网恢复后执行。涉及启动、配方和参数写入的命令必须受设备能力、操作权限和现场安全条件限制；平台不得绕过 PLC 安全联锁。

## 7. 设备配置与批量部署

设备接入向导按以下顺序运行：

1. 选择设备类别和协议驱动。
2. 填写 IP、端口、串口、证书或目录等连接参数。
3. 测试连接和身份。
4. 浏览或配置寄存器、节点、字段和采集周期。
5. 将厂家字段映射到标准事件字段。
6. 绑定工厂、车间、产线、工位、设备台账和 MES 工序。
7. 使用模拟或真实设备执行验证。
8. 生成配置版本并发布。

配置模型支持寄存器地址、数据类型、字节序、倍率、单位、质量码、采集频率、超时、重试、去抖、读写权限和敏感字段。无代码规则支持条件判断、数值转换、枚举转换、过滤、聚合、报警和事件联动。

同型号设备使用模板批量创建；1000 台设备可以通过 Excel/CSV 导入。OPC UA、MQTT 和部分局域网设备可自动发现，无法发现或涉及安全写入的设备必须人工确认。

配置发布使用不可变版本。支持按单设备、设备组、网关和工厂进行灰度发布；发布前校验驱动、权限和冲突，失败自动恢复上一版本。

## 8. 离线运行与数据一致性

### 8.1 离线业务快照

中央 MES 向网关下发带版本和有效期的业务快照，内容仅包含网关负责设备所需的工单、任务、工艺步骤、SN状态、产品模板、质量规则和授权设备。快照必须签名并原子替换。

断网时，网关只允许在最新有效快照覆盖范围内准入生产。规则缺失、快照过期、状态冲突或无法确定时，按客户配置执行失败关闭或进入受控人工放行；人工放行必须有权限、原因和审计，不得静默放行。

### 8.2 本地持久化与补传

关键事件先写入网关本地持久化队列，再向设备确认。默认保留不少于 7 天，容量按客户实际事件速率配置，并在剩余空间低于阈值时告警。

恢复网络后，同一设备事件严格按序补传，不同设备并行。中央接收成功后返回持久化确认，网关才可根据保留策略清理本地记录。重复传输通过 `event_id` 幂等，序列缺口触发补传或人工处置。

中央 MES 产生的报工、过站、质量记录和设备状态更新必须使用事件幂等键，确保同一事件最多产生一次业务结果。

### 8.3 NG 和复测

`quality.completed=NG` 必须将 SN 置为不良待处置状态，不能自动重新准入同工序。复测、返修、让步接收和报废由 MES 明确审批并生成新的处置或复测关联 ID。OK 是否立即放行下一工序由客户业务规则决定，默认要求质量事件和自动报工均成功落库后才过站。

## 9. 高可用与监控

### 9.1 边缘主备

设备所有权使用带任期的租约。网关只有在持有有效租约时才能采集或下发写命令。网络分区时采用防双主策略；无法确认租约的网关停止写控制，但可按配置保留只读诊断。

主备配置和未确认事件通过客户内网受控同步或由共享中央状态协调。对不能同时建立两个客户端连接的设备，由活动网关独占连接。

### 9.2 中央服务

1000 台规模的正式环境使用 PostgreSQL 主备或客户认可的高可用方案、MQTT 集群和至少两个中央应用实例。任何应用实例都不得保存无法恢复的本地会话状态。

### 9.3 可观测性

平台监控实际端口、插件进程、连接会话、最后数据时间、采集延迟、消息速率、序列缺口、未确认事件、补传积压、磁盘、CPU、内存、证书和配置版本。仅有“端点已启用”不能视为在线。

设备掉线、驱动崩溃、网关切换、快照过期、消息积压、磁盘将满、补传失败、数据库异常、证书即将到期和授权进入宽限期必须生成告警。

## 10. 安全与审计

- 网关与中央平台使用双向 TLS，网关拥有独立证书和可撤销身份。
- 管理 API 使用 HTTPS、基于角色的权限和最小权限原则。
- V1、Modbus RTU 等老旧明文协议限制在隔离 OT 网络，并使用防火墙、IP 白名单和网络访问控制。
- 密钥、证书私钥和协议凭据加密保存，不在普通日志和前端接口中返回。
- 插件声明网络、串口、文件和系统资源权限；未经授权不能访问 MES 数据库和任意文件。
- 原始报文展示和录包导出执行权限控制及敏感数据脱敏。
- 配置保存、发布、回滚、插件安装、驱动升级、设备命令、人工放行、生产准入、报告导入和授权变更均记录不可抵赖的审计信息。
- 软件包、插件包、配置包和离线升级包均进行数字签名验证。

## 11. 备份、升级与灾难恢复

数据库每天全量备份并持续增量或日志归档；备份同时保存到本机和异机位置。文件归档、网关配置、证书、授权和插件包纳入备份范围。升级前自动创建可恢复快照，并定期执行恢复演练。

中央平台、网关和插件采用分批升级。升级先在测试设备或单网关验证，再扩大范围；失败自动回滚。生产中的设备不能被未计划升级强制中断。

离线客户使用签名升级包。升级程序执行版本兼容、磁盘空间、数据库迁移和回滚条件预检，并输出机器可读及人工可读结果。

## 12. 现有 MES 改造边界

保留现有基础资料、工艺路线、订单、计划、工单、任务、报工、质量、库存、追溯和PC/客户端业务页面。

需要逐步替换或重构：

- Web 进程内的 AIM 专用监听和采集生命周期。
- AIM 专用报文、端点和 CSV 业务耦合。
- 作为中央生产数据库的 SQLite。
- 固定操作人 ID、固定设备和固定工序规则。
- 只统计数据库行数的设备健康状态。
- 缺少标准事件、命令、幂等和离线快照的业务接口。

迁移期间保留现有 AIM 接口兼容层，将其数据转换为标准事件。完成同等功能和数据核对后，才停用旧路径，避免一次性替换影响现有试用数据。

## 13. 分阶段交付

### 13.1 第一期：可验证的平台底座

- 标准事件和命令模型。
- 单工厂边缘网关基础程序和本地队列。
- MQTT 通讯、断网缓存和幂等补传。
- TCP、串口、USB HID、HTTP 和文件插件。
- AIM 现有方案迁移为插件。
- 中央工厂、网关、设备、驱动和配置版本管理。
- 以单工厂 20 台设备完成试点。

### 13.2 第二期：主流工业协议与配置能力

- Modbus TCP/RTU、OPC UA、Siemens S7、MQTT、EtherNet/IP、SMB/SFTP 和数据库插件。
- 接入向导、字段映射、无代码规则、模板库和批量导入。
- 自动发现、模拟器、录包回放和通讯诊断。
- 单工厂 100 台设备并发验证。

### 13.3 第三期：多工厂与高可用

- 10 个工厂和每厂双网关主备。
- MQTT、PostgreSQL 和中央服务高可用。
- 灰度发布、回滚、统一监控、告警和审计。
- 1000 台设备容量和灾难场景测试。

### 13.4 第四期：商业化私有部署

- Windows/Linux、Docker 和无公网离线安装。
- 白标品牌、签名授权和宽限策略。
- 离线升级、备份恢复和安装前检查。
- 插件 SDK、合作伙伴文档、客户交付和验收工具。

### 13.5 第五期：高级设备应用

- OEE、能耗、设备状态分析和看板。
- 预测性维护数据接口。
- 云边模型或规则包下发。
- 更多机器人、机床、视觉和检测厂商插件。

## 14. 验收标准

商业可交付版本至少满足：

1. 10 个逻辑工厂、1000 台模拟设备连续运行 72 小时，无不可恢复服务中断。
2. 单厂与中央断网 7 天，在有效离线快照和本地容量范围内继续生产；恢复后自动补传。
3. 所有补传事件无重复报工、重复过站或重复质量记录，序列缺口可发现和恢复。
4. 活动边缘网关故障后备用网关自动接管，接管期间不存在双重采集或重复控制。
5. 单个插件崩溃不影响网关主进程和其他设备，并能自动恢复或隔离告警。
6. 配置和插件分批发布失败可以恢复上一有效版本。
7. 设备命令具有完整状态、超时和审计，过期命令不会在断网恢复后误执行。
8. 客户可以在无公网环境完成安装、激活、升级、备份和恢复。
9. 品牌配置不需要创建代码分支，核心升级可用于所有白标版本。
10. 数据库、设备配置、证书、插件、授权和原始文件均能完整备份并通过恢复演练。
11. 权限、安全、并发、网络分区、磁盘耗尽、突然断电和灾难恢复测试通过。

## 15. 关键设计决策

1. 选择边缘网关集群，而不是让 1000 台设备直接连接中央 MES。
2. 首期只支持私有化部署，不建设公共云多租户 SaaS。
3. 使用单一核心代码配合白标配置，不维护合作伙伴专属代码分支。
4. 默认不交付核心源码，使用签名安装包和插件 SDK 扩展。
5. 先建设协议插件底座和标准事件，再逐步增加协议，避免在 MES 核心堆积设备特例。
6. 断网生产依赖有版本和有效期的本地业务快照，并坚持事件持久化、幂等和有序补传。
7. 工业安全联锁始终留在 PLC 和现场安全系统，设备平台不承担安全控制职责。
