# MES 全业务列表手工排序设计

## 背景

系统已经支持按表头字段升序、降序排列，但用户还需要直接调整记录的业务显示位置。例如，一张表有 10 条记录时，应能把当前第 9 条移动到第 6 条，并在刷新、重新登录或更换电脑后继续保持这个位置。

## 目标

- 所有记录型业务列表统一支持“上移、下移、移动到指定排列 ID”。
- 表格第一列 `ID` 表示可变的排列 ID；记录移动后该 ID 随位置重新编号。
- 数据库真实主键继续作为隐藏内部标识，永不因列表移动而修改。
- 手工顺序持久化到数据库，并按模块独立保存。
- 不给看板卡片、统计图、摘要表、对比表增加手工排序。
- 与现有字段升降序明确共存，不产生顺序冲突。
- 不删除、不清理现有业务记录和已保留测试数据。

## 数据设计

新增独立表 `sys_table_order`：

| 字段 | 说明 |
| --- | --- |
| `id` | 主键 |
| `table_key` | 业务列表唯一标识，例如 `prod/workorder` |
| `record_id` | 对应业务记录 ID |
| `position` | 从 1 开始的全局显示位置 |
| `updated_at` | 最后调整时间 |

`table_key + record_id` 建立唯一约束，`table_key + position` 建立查询索引。`record_id` 是隐藏的数据库真实主键，`position` 是用户在表格第一列看到的排列 ID。顺序表只保存显示顺序，不修改业务表主键、外键或业务含义。

数据库真实主键不能参与交换。项目中的 `workorder_id`、`task_id`、`product_id` 等外键依赖真实主键；直接交换主键会造成工单、任务、报工、库存和追溯串联错误。前端编辑、删除和关联请求继续使用隐藏的 `record_id`。

## 后端接口

新增统一接口：

- `GET /api/table-order/<table_key>`：返回指定模块的记录位置映射。
- `POST /api/table-order/move`：接收 `table_key`、`record_id`、`target_position`，在事务中重新编号。
- `POST /api/table-order/step`：接收 `table_key`、`record_id`、`direction`，执行上移或下移。

后端维护允许排序的模块白名单，并将每个 `table_key` 映射到真实业务表和主键。客户端不能提交任意表名。移动时先读取该模块当前全部有效记录 ID；没有顺序记录的数据按原默认顺序接在末尾，再把目标记录插入指定位置并统一写回连续的 `1..N`。目标位置小于 1 时使用 1，大于总数时使用总数。

删除业务记录后，读取顺序时忽略失效 ID；下一次移动会自动压缩空位。新记录没有顺序项时默认出现在已排序记录之后。

## 前端交互

所有记录型表格不再额外增加“顺序”列。现有第一列 `ID` 改为显示当前全局排列 ID，并在操作区增加三个顺序操作：

- `↑`：上移一位。显示 ID 8 的记录上移后变成 ID 7，原 ID 7 的记录变成 ID 8。
- `↓`：下移一位。显示 ID 7 的记录下移后变成 ID 8，原 ID 8 的记录变成 ID 7。
- `移到`：打开紧凑输入框，输入目标排列 ID 并确认。例如显示 ID 9 的记录输入 `6` 后变成 ID 6，原 ID 6 至 ID 8 的记录依次变成 ID 7 至 ID 9。

第一列单元格通过位置映射显示 `1..N`，行元素通过不可见 `data-record-id` 保存真实主键。操作成功后重新加载当前列表并保留搜索条件和分页状态。ID 1 的上移、ID N 的下移禁用。

当用户通过表头选择字段升序或降序时，第一列仍显示该记录持久化的排列 ID，不按当前视觉行号临时重编；移动操作禁用，提示“请先恢复默认顺序再调整”。第三次点击表头恢复默认排序后，继续按排列 ID 排列并允许调整。

## 分页与搜索

排列 ID 始终是模块全量数据的全局编号，不是当前页内编号。第 2 页的记录可以直接移动到排列 ID 6，完成后页面跳转到包含新 ID 的页。

搜索结果只用于查找记录；移动仍针对完整模块顺序。目标编号也是全局排列 ID，界面在输入框旁明确显示“目标排列 ID”。

## 覆盖范围

覆盖现有后台中所有真正呈现业务记录集合的列表，包括基础资料、库存、生产、质量、设备、工装、能源环境、人力、5S、售后、审批、排班、工具、文档、通知和系统记录。查询结果表在可以唯一识别业务记录时支持手工排序；统计汇总、图表、看板、技能矩阵等非记录型表格排除。

首批验收必须覆盖：工单、任务、报工、库存余额、来料检验、设备台账、产品定义、用户管理。其他记录表通过统一组件和模块注册表获得相同行为。

## 权限与错误处理

- 必须登录才能读取和调整顺序。
- 调整接口沿用后台管理权限；无权限返回明确错误，不改变顺序。
- 记录不存在、模块不在白名单、目标位置非法时返回业务错误。
- 写入在单个数据库事务内完成，失败时整体回滚。
- 前端请求失败时恢复按钮状态并显示服务端错误，不假装成功。

## 测试与验收

1. 单元测试验证显示 ID 8 上移后变为 ID 7、原 ID 7 变为 ID 8，同时数据库真实主键不变。
2. 单元测试验证将显示 ID 9 移动到显示 ID 6 后的完整排列 ID 映射。
3. 测试上移、下移、边界位置、无效模块、失效记录和连续编号。
4. API 测试验证事务、权限、白名单和跨分页移动。
5. 前端测试验证第一列显示排列 ID、真实主键隐藏、按钮、目标 ID 输入、字段排序时禁用和错误提示。
6. 浏览器使用现有记录做无删除验收：把工单排列 ID 调整后刷新确认持久化，并验证编辑/删除按钮仍指向原真实记录；测试完成后保留调整结果，不清理业务数据。

## 验收标准

- 用户能将显示 ID 9 的记录准确移动到显示 ID 6。
- 用户将显示 ID 8 上移后，它显示为 ID 7，原 ID 7 显示为 ID 8。
- 移动前后的数据库真实主键、业务单号和外键关联完全不变。
- 刷新、重新登录和其他浏览器看到相同顺序。
- 每个模块顺序互不影响。
- 表头升降序和手工排序不会同时生效。
- 新增、删除和分页不会产生重复位置或断裂的可见顺序。
- 自动化测试和浏览器验收全部通过。
