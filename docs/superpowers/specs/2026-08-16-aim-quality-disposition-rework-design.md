# AIM 不良处置与返工闭环设计

## 目标与范围

为 AIM 机台检测产生的 NG 结果建立可审核、可追溯的质量处置与返工闭环。第一阶段覆盖返工、报废和让步接收，并修正生产任务错误地将不良数视为合格产出的完成规则。历史 AIM 标准事件回填作为独立阶段，不包含在本设计中。

## 已确认的根因

当前 NG 导入会生成不良报工和 FAIL 工站记录，但没有创建 SN 级质量处置状态。报工过账又以“合格数加不良数达到计划数”关闭任务；机台准入只接受进行中的任务，因此不良 SN 再次扫码得到 `TASK_UNAVAILABLE`。现有 `prod_rework` 仅记录工单和数量，`/api/process/rework` 仅写工站流转，两者都没有关联原报告、SN、冻结路线或可执行返工任务。

## 数量原则

- 普通生产任务只有在 `completed_qty >= planned_qty` 时完成。
- `defect_qty` 是质量损失累计，不能代替最终合格产出。
- 原任务计划数量表示最终合格品数量。
- 返工成功时，返工任务完成，同时给原任务和工单补记一件合格品。
- 原始不良数永久保留，用于一次合格率、质量损失和追溯统计。
- 报废后原任务仍缺少合格产出，必须投入新的 SN 补产。

## 数据模型

### SN 质量状态

为 `prod_serial` 增加 `quality_status`，允许值：

- `normal`：正常生产。
- `quality_hold`：NG 后待质量处置，禁止机台准入。
- `rework`：已批准返工，只有关联且已启动的返工任务可以准入。
- `scrapped`：已报废，永久禁止准入。
- `concession`：让步接收，允许按审批结果过站。

原有整数 `status` 保留兼容，不用于表达细分质量状态。

### 质量处置单

新增 `prod_quality_disposition`，主要字段为：

- `disposition_no`：唯一处置单号。
- `sn`、`inspection_report_id`、`machine_request_id`、`prod_report_id`。
- `workorder_id`、`source_task_id`、`route_step_id`。
- `action`：`pending`、`rework`、`scrap` 或 `concession`。
- `status`：`pending_review`、`approved`、`task_started`、`completed`、`rejected`。
- `rework_task_id`、`cycle_no`、`reason`。
- `reviewer_id`、`reviewed_at`、`created_at`、`completed_at`。

同一检测报告只能生成一个处置单。同一 SN 和工艺步骤同一时间只能有一个未完成处置单。

### 返工任务

为 `prod_task` 增加：

- `task_type`：`normal` 或 `rework`。
- `source_task_id`：原生产任务。
- `quality_disposition_id`：来源处置单。
- `target_sn`：本返工任务唯一允许处理的 SN。

返工任务计划数固定为 1，初始状态为草稿。质量审批不能自动启动任务。

## 状态与业务流

### NG 入库

CSV 导入在同一事务中完成：

1. 保存检测报告、测量项和不良报工。
2. 保存 FAIL 工站记录，但不生成 PASS。
3. 将 SN `quality_status` 设置为 `quality_hold`。
4. 创建 `pending_review` 质量处置单。
5. 将 AIM 请求标记为已收到报告。

重复 CSV 返回已有报告和处置单，不产生重复记录。

### 准入判定

准入服务在普通任务查询前检查 SN 质量状态：

- `quality_hold` 返回 L3 `QUALITY_HOLD`。
- `scrapped` 返回 L3 `SN_SCRAPPED`。
- `rework` 只接受处置单关联的返工任务；任务未启动返回 `REWORK_TASK_NOT_STARTED`。
- `concession` 已完成过站时按已有 PASS 规则返回 `ROUTE_COMPLETED`。
- `normal` 沿用现有冻结路线和普通任务规则。

### 批准返工

质量人员将待审核处置单批准为返工时，系统在一个事务中创建草稿返工任务，关联原任务、处置单、工序和 SN，并把 SN 状态改为 `rework`。重复审批返回已有返工任务。

生产主管通过受控状态转换启动返工任务。启动前机台拒绝准入；启动后只允许 `target_sn` 在原工艺步骤获得 L1。

### 返工 OK

返工报告审核过账后：

- 返工任务 `completed_qty` 增加 1 并完成。
- 原任务 `completed_qty` 增加 1，达到计划数时完成。
- 工单 `completed_qty` 增加 1。
- 原任务和工单的历史 `defect_qty` 不减少。
- SN 状态恢复为 `normal`。
- 生成 PASS 工站记录，处置单标记为 `completed`。

### 返工再次 NG

当前返工任务只增加 `defect_qty`，不完成。原处置单结束本次返工周期，同时创建下一轮 `pending_review` 处置单，`cycle_no` 增加，SN 回到 `quality_hold`。

### 报废

质量人员批准报废后，SN 状态设置为 `scrapped`，处置单完成，不创建返工任务。任何机台再次扫码均返回 `SN_SCRAPPED`。原任务合格数量不增加。

### 让步接收

质量人员批准让步接收后，系统为原工艺步骤生成带处置单关联的 PASS 过站记录，SN 状态设置为 `concession`，处置单完成。原不良记录保留，不额外生成合格报工。

## 服务与接口边界

新增独立质量处置服务，集中负责创建、审批、启动校验和完成处置，不允许蓝图直接拼装数据库更新。

管理接口：

- `GET /api/site/rework/list`：返回 SN、原报告、工单、工序、处置方式、返工次数和任务状态。
- `POST /api/site/rework/<id>/approve`：质量人员选择 `rework`、`scrap` 或 `concession`。
- `POST /api/site/rework/<id>/reject`：驳回错误处置单，不解除质量冻结。
- 返工任务启动继续使用生产任务受控状态转换，但服务端校验其来源处置单和当前 SN 状态。

审批类接口要求管理员或质量权限；任务启动要求管理员或生产任务权限；普通登录用户只能查看其获授权的数据。

## 页面设计

“返工报废”页面从工单数量级 CRUD 升级为 SN 质量处置列表，显示：

- 处置单号、SN、原检测报告、工单、工序和设备。
- 不良原因、处置状态、返工周期。
- 返工任务及其草稿、进行中、完成状态。
- 审核返工、报废、让步接收和启动返工任务操作。

序列号列表显示细分质量状态，不再把所有非零状态统一显示为“已使用”。机台通讯报告列表显示关联处置单和处理状态。

## 幂等、并发与错误处理

- NG 导入、处置单创建和 SN 冻结属于同一事务。
- 审批使用条件更新，仅 `pending_review` 可审批。
- 数据库唯一约束防止同报告重复处置及同 SN/步骤多个开放处置。
- 返工任务启动前再次扫码不会创建普通任务请求。
- 返工报告过账在一个事务中更新返工任务、原任务、工单、SN 和处置单。
- 重复过账返回原结果，不重复累计。
- 任何事务失败保持 SN 冻结并记录明确错误，不默认放行。

## 迁移与现有数据

迁移只增加字段、处置表、索引和约束，不删除现有表。对已有未处置 NG 报告执行幂等回填：创建待审核处置单并将关联 SN 置为 `quality_hold`。本次测试 SN `SIM-AIM-20260816-002` 应被回填为待处置，报告 ID 4 作为来源。

现有普通任务的状态不批量改写；新规则在后续报工过账或显式重算时生效。工单 13 在测试时通过业务服务重算，预期原任务由“已完成”恢复为“进行中”。

## 验收测试

- NG 自动创建唯一处置单并冻结 SN。
- 冻结 SN 返回 `QUALITY_HOLD`。
- 批准返工创建一条草稿返工任务，重复审批不重复创建。
- 草稿返工任务返回 `REWORK_TASK_NOT_STARTED`，启动后返回 L1。
- 返工 OK 后返工任务、原任务、工单、SN 和处置单状态一致。
- 返工 NG 创建下一周期且不完成返工任务。
- 报废永久阻断准入。
- 让步接收生成唯一 PASS，不增加合格报工。
- 普通任务不再因不良数达到计划数而完成。
- 并发审批、重复 CSV、重复请求和重复过账保持幂等。
- 原 AIM OK、普通生产报工、任务状态转换及完整测试套件通过。
