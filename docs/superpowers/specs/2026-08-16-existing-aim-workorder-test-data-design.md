# 现有 AIM 工单软件联调数据设计

## 目标

使用现有工单 `TEST-AIM-FILE-WO`（ID 13）验证真实生产链路，不创建新的工单，也不修改其他工单的工艺路线、任务或完成数量。

## 选定业务数据

- 工单：`TEST-AIM-FILE-WO`，计划数量 2，状态为进行中。
- 冻结路线：工单现有路线快照及 AIM 工序步骤。
- 任务：`TEST-AIM-FILE-TASK`，状态为已启动。
- 设备：`TEST-AIM-FILE-DEVICE`。
- 通讯端点：现有 V2 AIM 端点，工站和穴位沿用数据库配置。

## 新增数据

只新增两条序列号，并绑定工单 13 及其产品：

- `SIM-AIM-20260816-001`：用于 OK 准入、检测、报工和过站闭环。
- `SIM-AIM-20260816-002`：用于 NG 检测、不良报工和待处置闭环。

两条记录状态均初始化为可生产。测试请求号、CSV 文件名和后续报工备注统一使用 `SOFT-SIM-20260816` 前缀，便于在页面和数据库中识别。

## 执行边界

- 不删除或修改已有序列号。
- 不更改工单计划数、完成数、不良数和状态；这些字段只允许后续正式业务流程自行重算。
- 不直接插入报工、过站或不良结果，由机台模拟器和 CSV 导入接口生成。
- SN 插入采用事务和唯一性检查；重复执行时返回既有记录，不重复创建。

## 验收流程

1. 校验两个 SN 均绑定工单 13、产品一致、状态可生产。
2. 使用 V2 模拟器分别请求两个 SN，预期取得 `L1`。
3. 为第一个 SN 导入 OK CSV，检查待审核报工、审核/过账及 PASS 过站。
4. 为第二个 SN 导入 NG CSV，检查不良报工和待处置状态。
5. 重发相同请求和重复导入同一 CSV，确认幂等，不重复累计。
6. 对比工单与任务在测试前后的完成数和不良数。

## 成功标准

- 两个 SN 均能通过现有工单进入 AIM 准入判断。
- OK 和 NG 分别进入正确业务分支。
- 重复请求不产生重复报工或重复过站。
- 除工单 13 以外的生产数据不发生变化。
