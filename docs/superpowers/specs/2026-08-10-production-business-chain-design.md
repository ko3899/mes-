# MES 生产业务链补全设计

## 1. 目标

补全 MES 工厂管家中销售订单、生产计划、工艺路线、工单、任务、生产领料、报工和工序转移的页面与业务关联，使系统能够实际执行一条可追溯的生产流程，并防止不同产品、不同车间的工序被错误混用。

本次采用 A+ 订单驱动方案，不新增独立的“项目管理”实体。一次生产项目由“销售订单 → 生产计划 → 生产批次 → 工单”表示，工单是任务、领料、报工、转移和后续追溯的核心业务标识。工单下达时冻结工艺路线和 BOM，避免生产过程中基础资料变更影响已投产工单。

## 2. 已确认的根因

1. `renderSales`、`renderPlan`、`renderTask`、`renderReport2`、`renderRoute` 五个前端渲染函数缺失。菜单点击后抛出 JavaScript 异常，页面内容未清空，因此继续显示上一个模块，截图中表现为销售订单和生产计划仍显示“客户管理”。
2. 数据库已有销售订单明细、计划明细，以及工单关联销售订单、计划、产品、路线和车间的字段，但页面和部分 API 只实现了单据头或极少数字段。
3. 工序已有 `workshop_id`，但允许为空；任务和工序转移直接加载全部工序，没有按工单车间及产品工艺路线过滤。
4. 生产领料只有基础记录，没有 BOM 带料、库存校验和库存事务联动。
5. 工单新增页面没有暴露数据库已有的计划、销售订单、车间、路线、日期和备注字段。

## 3. 业务模型

### 3.1 核心链路

```text
客户
  → 销售订单及订单明细
  → 生产计划及计划明细
  → 生产批次
  → 生产工单
  → 工单工艺路线快照
  → 工序任务
  → 工单 BOM 快照与生产领料
  → 生产报工与工序转移
  → 工单完成、成品入库、报表与追溯
```

### 3.2 工序归属

- 工序是可复用的生产能力，`workshop_id` 表示默认执行车间，对新建和编辑操作必填。
- 旧工序可以暂时保留空车间并显示“未分配车间”，但再次编辑或用于新路线前必须补齐。
- 产品通过工艺路线选择工序，避免在工序主数据上重复绑定多个项目或产品。
- 工艺路线步骤明确记录实际执行车间，只允许选择该车间的启用工序；同一基础工序可被不同产品路线复用。
- 任务和工序转移只能使用当前工单所选工艺路线中的工序。

### 3.3 单据关系

- 销售订单包含一个单据头和一条或多条产品明细。
- 生产计划可关联销售订单，并包含一条或多条计划明细。
- 生产计划明细可以拆分为一个或多个生产批次，同一订单可以分批投产和交付。
- 工单可关联销售订单与生产计划，且必须指定产品、车间和工艺路线。
- 工单的产品、车间和路线必须相互匹配。
- 任务属于工单和路线步骤。
- 领料记录属于工单，物料优先来自工单产品的 BOM。
- 报工属于任务，并由任务推导工单、工序和当前操作员。
- 工序转移属于工单，只允许在路线中的相邻工序之间执行。

### 3.4 生产冻结与版本

- 产品工艺路线具有版本号；工单下达时复制路线及步骤到工单路线快照。
- 产品 BOM 具有版本标识；工单下达时按计划数量计算并复制物料需求到工单 BOM 快照。
- 工单下达后修改产品路线或 BOM，只影响以后创建的工单，不改变正在生产或已经完成的工单。
- 工单草稿阶段可以重新选择路线并刷新快照；工单下达后不得直接刷新，只能通过受控变更操作形成变更记录。

### 3.5 可执行数量

- 首道工序可执行数量取工单计划数量减去首道工序已报工数量。
- 后续工序可执行数量取上一工序累计合格转入数量减去当前工序累计报工数量。
- 工序转移减少来源工序可转移数量并增加目标工序可执行数量。
- 包装和成品入库数量不得超过最后一道工序累计合格数量减去已包装或已入库数量。

## 4. 页面与字段设计

### 4.1 工序管理

列表字段：排列 ID、工序名称、编码、所属车间、标准工时、状态、操作。

筛选条件：车间、工序名称或编码、状态。

新增/编辑字段：

- 所属车间，必填
- 工序名称，必填
- 工序编码，必填且唯一
- 标准工时（分钟）
- 描述
- 状态

已被工艺路线引用的工序不能直接删除，只能停用。

### 4.2 工艺路线

路线字段：路线名称、适用产品、默认车间、版本、状态、描述。

路线明细字段：步骤号、执行车间、工序、标准工时、是否检验点、描述。支持上移、下移和移动到指定步骤。路线内不得重复添加相同工序。

### 4.3 销售订单

单据头字段：自动订单号、客户、联系人、电话、交货日期、总金额、状态、备注。

订单明细字段：产品、数量、单价、金额、已交数量、备注。金额由数量乘以单价自动计算，总金额由所有明细汇总。

状态：草稿 → 已确认 → 生产中 → 已完成；草稿和已确认状态允许取消。

### 4.4 生产计划

单据头字段：自动计划号、关联销售订单、计划类型、开始日期、结束日期、状态、备注。

计划明细字段：产品、计划数量、已完成数量、生产车间、备注。

选择销售订单后，可自动带入未完成的订单产品明细。计划结束日期不得早于开始日期。

状态：草稿 → 已发布 → 执行中 → 已完成；草稿和已发布状态允许取消。

### 4.5 生产批次

字段：自动批次号、计划明细、产品、计划数量、生产车间、计划开始日期、计划结束日期、状态、备注。

一个计划明细可以拆分多个批次，但所有有效批次数量之和不得超过计划明细的剩余数量。批次号贯穿工单、领料、报工、检验、入库和追溯。

### 4.6 工单管理

字段：自动工单号、关联销售订单、关联生产计划、生产批次、产品、生产车间、工艺路线版本、BOM 版本、计划数量、完成数量、不良数量、优先级、开始日期、结束日期、状态、备注。

选择计划明细后自动带入销售订单、产品、计划数量和生产车间。路线下拉框只显示当前产品与车间可用的启用路线。

工单由草稿变为已下达时，系统冻结路线和 BOM 快照；任务与领料需求都从快照生成，不再直接读取可能被修改的产品基础资料。

### 4.7 任务管理

字段：自动任务号、工单、工序、执行人员、计划数量、完成数量、不良数量、开始时间、结束时间、状态、备注。

选择工单后，工序只能从工单路线快照中选择；计划数量默认继承工单数量。提供“按冻结路线生成任务”，按快照步骤一次生成任务并防止重复生成。任务页面显示上游转入数量、当前可执行数量和剩余数量。

### 4.8 生产领料

字段：自动领料单号、生产批次、工单、物料、需求数量、申请数量、实发数量、已退数量、欠料数量、领料类型、仓库、库位、物料批次、状态、申请人、发料人、收料人、备注。

提供“按冻结 BOM 生成领料需求”。申请时允许分批申请；仓库发料时校验可用库存并扣减库存余额，同时写入库存事务；车间确认收料后完成领料；退料确认时增加库存并写入反向事务。

### 4.9 报工管理

字段：自动报工单号、生产批次、任务、工单、工序、操作员、可执行数量、合格数量、不良数量、报工时间、不良原因、备注。

选择任务后自动带出工单和工序，操作员取当前登录用户。提交报工只保存待审核记录；审核通过后执行记账，并在同一事务中累计任务和工单的完成数及不良数。驳回记录不参与任何生产数量累计。

### 4.10 工序转移

字段：自动转移单号、工单、来源工序、目标工序、数量、状态、操作员、时间、备注。

来源与目标工序必须是当前工单路线快照中的相邻步骤，转移数量不得超过来源工序已报工合格但尚未转出的可用数量。

### 4.11 受控状态操作

状态不再作为普通编辑字段任意修改，而由业务按钮推进：

| 模块 | 状态流转 |
|---|---|
| 销售订单 | 草稿 → 已确认 → 生产中 → 已交付；草稿/已确认可取消 |
| 生产计划 | 草稿 → 已发布 → 执行中 → 已完成；草稿/已发布可取消 |
| 生产批次 | 草稿 → 已排产 → 生产中 → 已完成/已取消 |
| 工单 | 草稿 → 已下达 → 生产中 → 暂停 → 已完工 → 已关闭 |
| 任务 | 待开始 → 进行中 → 已完成/已暂停 |
| 领料单 | 草稿 → 待发料 → 已发料 → 已收料；已发料后可部分退料 |
| 报工单 | 已提交 → 已审核 → 已记账/已驳回 |

每次状态变化写入操作日志，记录业务类型、业务 ID、原状态、新状态、操作人、时间和备注。

## 5. API 与数据层设计

### 5.1 查询 API

列表 API 返回页面直接需要的关联名称，避免前端把外键数字当作业务文本显示：

- 销售订单返回客户名称和订单明细。
- 生产计划返回销售订单号和计划明细。
- 工单返回订单号、计划号、产品、车间和路线名称。
- 任务返回工单号、产品、车间、路线步骤和工序名称。
- 领料返回工单号、产品、物料、仓库、批次和库存信息。
- 报工返回任务号、工单号、工序和操作员名称。

增加依赖选择接口：

- 根据产品和车间查询可用路线。
- 根据路线查询有序工序步骤。
- 根据工单查询允许创建的任务工序。
- 根据工单快照查询有序步骤和当前可执行数量。
- 根据工单冻结 BOM 查询领料需求、已领、已退和欠料数量。
- 根据计划明细查询可拆分的剩余批次数量。

### 5.2 写入 API

单据头和明细在同一数据库事务内保存。任何明细失败时整单回滚，不允许产生只有单据头、没有明细的半成品数据。

业务写入不使用无约束的通用 CRUD，必须显式白名单字段、校验外键关系和数量规则。

### 5.3 数据库迁移

在现有初始化迁移机制中增量增加缺失字段，不删除或重建现有表：

- 工艺路线增加 `workshop_id`、`version`。
- 工艺路线明细增加 `workshop_id`、`is_inspection_point`。
- 新增生产批次表，关联计划明细、产品和车间。
- 新增工单路线快照表及步骤表，保存路线版本和冻结步骤。
- 新增工单 BOM 快照表，保存物料、单位用量、计划需求和 BOM 版本。
- 生产领料增加 `production_batch_id`、`required_qty`、`requested_qty`、`issued_qty`、`returned_qty`、`warehouse_id`、`location_id`、`material_batch_no`、`remark`、`issued_at`、`received_at`。
- 报工按现有缺陷记录结构补充可关联的不良原因字段；如果已有等价字段则复用。
- 新增统一业务状态日志表。
- 为订单明细、计划明细、路线明细、任务和领料常用外键增加索引。

## 6. 校验与错误处理

- 销售订单至少包含一条数量大于零的产品明细。
- 计划至少包含一条明细，日期范围有效。
- 工单数量大于零，产品、车间、路线一致。
- 有效生产批次数量之和不得超过计划明细剩余数量。
- 任务工序属于工单路线。
- 领料物料属于 BOM，手动补料必须写明备注。
- 库存不足时拒绝确认领料，并返回物料、需求、可用和缺少数量。
- 报工数量非负，且累计合格数加不良数不得超过任务计划数量。
- 后续工序报工不得超过上游转入的当前可执行数量。
- 已下达工单只能读取冻结路线和冻结 BOM，不能被基础资料修改反向影响。
- 已进入执行状态的单据不允许直接删除。
- 页面渲染前先清空旧内容；渲染函数缺失或 API 失败时显示模块级错误卡片，不再保留上一个模块。

## 7. 旧数据兼容

- 不删除现有生产和测试数据。
- 旧工序空车间显示“未分配车间”，在编辑或新引用时要求补齐。
- 旧销售订单或计划没有明细时显示“待补充明细”，允许编辑补齐。
- 旧工单没有路线或车间时继续显示，但生成新任务前必须补齐。
- 旧工单不强制补建快照；首次执行“下达”或“补全生产资料”时，根据当时路线和 BOM 生成一次快照。
- 已有任务、报工和外键 ID 保持不变。
- 真实数据库 ID 保持隐藏，现有排列 ID 功能继续生效。
- 新增验收数据统一在备注中标记“生产业务链测试”，测试后保留。

## 8. UI 设计

- 延续现有企业蓝色主题和表格密度。
- 单据页面采用“单据头 + 明细表”结构，新增和编辑使用较宽的业务弹窗。
- 依赖字段使用逐级选择和禁用状态，例如未选产品和车间前禁用路线。
- 自动带出的字段使用浅蓝只读样式，并在字段下方说明来源。
- 状态操作与数据编辑分开，发布、确认、开始、完成等动作提供明确二次确认。
- 宽表继续使用横向滚动，操作列保持在最后，不破坏现有排序和排列 ID 控件。

## 9. 测试与验收

### 9.1 自动测试

- 静态检查五个缺失渲染函数均已实现并由菜单正确调用。
- API 测试覆盖订单头明细事务、计划带入、批次拆分、路线/BOM 快照、路线过滤、任务生成、分批领退料、库存不足、报工累计、上游可执行数量与超量拒绝。
- 迁移测试覆盖旧数据库升级和旧数据保留。
- 前端测试覆盖依赖下拉、必填校验、金额计算、状态操作和失败页面。
- 原有 Node 与 Python 全量测试必须全部通过。

### 9.2 浏览器验收

保留一套备注为“生产业务链测试”的数据，完整跑通：

```text
客户 → 销售订单及明细 → 生产计划及明细 → 生产批次 → 工单
→ 冻结路线生成任务 → 冻结 BOM 生成领料 → 仓库发料并扣库存
→ 报工 → 工序转移 → 工单完成 → 成品入库 → 报表与追溯
```

验收确认：

1. 五个缺失页面正常打开，不再显示上一个页面。
2. 不同产品和车间的工序不能混用。
3. 每一级单据能够追溯上下游业务编号。
4. 数量累计和库存变化正确。
5. 刷新、重新登录后数据一致。
6. 原有排序、排列 ID、编辑、删除和导出能力没有回归。
7. 修改产品路线或 BOM 后，已下达工单的快照和任务不发生变化。
8. 后续工序、包装和入库不能录入超过上游合格数量的数据。

## 10. 非目标

- 本次不新增独立项目管理、项目成本或项目里程碑模块。
- 本次不重做全部仓储单据界面，只实现生产领料所需的库存联动。
- 本次不自动完成工单或自动成品入库；这些动作保留人工确认，避免生产数据被意外结转。
