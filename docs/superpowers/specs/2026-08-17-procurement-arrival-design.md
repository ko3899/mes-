# 采购、到货、检验与入库闭环设计

**日期：** 2026-08-17  
**范围：** 采购订单、到货登记、异常处置、来料检验、正式入库  
**目标：** 将现有只读到货通知模块改造成可在工厂实际使用、全程可追溯的受控业务闭环。

## 1. 背景

现有 `inv_arrival_notice` 只具备基础表结构，旧写入接口允许直接增删改字段，但没有采购来源、数量累计、审核、异常到货、退货、检验、入库幂等和审计控制。继续使用旧接口可能造成采购数量、质检结论和库存余额不一致，因此旧写入入口保持停用，改由领域服务承载正式流程。

到货是客观事实。即使采购订单不存在、未审核或供应商超量送货，系统也必须允许登记实际到货，但不得直接形成可用库存。

## 2. 实施范围

本阶段采用“生产可用版”，包括：

- 采购订单及明细。
- 采购主管审核。
- 正常和异常到货登记。
- 分批到货与累计数量。
- 部分接收、部分退货和待处理。
- 超量到货特批。
- 必检、抽检、免检。
- 合格、让步接收和退货处置。
- 按仓库、库区、库位和物料批次正式入库。
- 库存余额、库存流水、状态日志和审计记录。

本阶段不包含询价、比价、采购合同、发票、应付和付款；这些属于后续供应链与财务模块。

## 3. 核心单据

### 3.1 采购订单

采购订单记录供应商、交期、币种、备注和审核信息；订单明细记录物料、采购数量、单价、税率、累计到货、累计接收、累计退货和剩余数量。

状态：

`草稿 → 待审核 → 已审核 → 部分到货 → 全部到货 → 已关闭`

另有“审核驳回”和“已取消”。已发生到货的订单不得取消，只能关闭并保留原因。订单审核后，供应商、物料、采购数量等关键字段不得通过通用更新接口修改。

### 3.2 到货单

到货单记录实际到厂事实，包括采购订单、供应商送货单号、到货时间、车辆或送货人员和备注。到货明细记录实际到货数量及其采购订单明细来源。

无采购订单、订单未审核、供应商不匹配或超采购数量时仍允许登记，但状态为“异常待处理”。

状态：

`已登记 → 待匹配/异常待处理 → 待收货 → 待检验 → 部分入库 → 全部完成`

退货时记录“部分退货”或“全部退货”，原到货事实和明细永久保留。

### 3.3 收货处置

每条到货明细可以多次处理，处理类型为接收、退货或继续待处理。数量恒等式为：

`累计接收数量 + 累计退货数量 + 当前待处理数量 = 实际到货数量`

异常到货允许三种处理：

1. 补充或修正采购订单后转为正常收货。
2. 采购主管特批接收，记录特批人、原因和时间。
3. 部分或全部退货，生成退货记录，不删除到货记录。

采购100件但实际到货110件时，100件可进入正常流程，超出的10件进入异常待处理；主管可特批接收或退货。

### 3.4 来料检验单

物料配置检验方式：必检、抽检、免检。

- 必检：接收数量全部进入检验流程。
- 抽检：记录抽样数量、缺陷和检验结果，再判定整批或指定数量。
- 免检：收货后可直接入库，但保留免检配置和判定依据。

检验处置包括合格、退货、返工/挑选、让步接收。让步接收必须由质量主管批准。

数量恒等式为：

`合格入库数量 + 让步入库数量 + 退货数量 + 待处理数量 = 已接收数量`

## 4. 业务数据流

正常流程：

`采购订单 → 提交审核 → 主管审核 → 到货登记 → 收货处置 → 来料检验/免检 → 正式入库 → 库存流水`

异常流程：

`无订单/未审核/超量到货 → 异常待处理 → 补单、特批或退货`

分批到货按采购订单明细累计数量。一张订单可以对应多张到货单，一张到货单可以分多次收货、检验和入库。

收货不等于入库。只有检验合格、免检或批准让步接收的数量才能增加库存。

## 5. 库存与幂等

正式入库必须选择仓库、库区、库位和物料批次。每次入库在同一个数据库事务中完成：

1. 锁定并检查可入库剩余数量。
2. 写入入库业务记录。
3. 更新对应仓库、库位和批次的库存余额。
4. 写入不可修改的库存流水。
5. 更新采购、到货和检验累计数量及状态。

每个入库请求携带客户端操作编号，并建立唯一约束。重复提交返回第一次结果，不得重复增加库存。并发收货、退货、检验和入库必须使用事务条件更新或等效锁定，累计数量不得超限。

## 6. 页面设计

### 6.1 采购订单

- 新增、编辑草稿、提交审核、审核通过、驳回、取消和关闭。
- 显示采购数量、累计到货、剩余未到、超量和退货数量。
- 订单明细支持多物料。

### 6.2 到货管理

- 从已审核采购订单创建正常到货。
- 允许登记无订单或未审核订单的异常到货。
- 填写实际到货明细、送货单号和到货时间。
- 执行接收、部分退货、全部退货和申请特批。

### 6.3 来料检验

- 根据物料检验方式生成检验任务。
- 记录抽样数量、合格数量、不合格数量、缺陷、附件和结论。
- 执行合格、退货、返工/挑选和让步接收。

### 6.4 入库

- 仅展示已通过检验、免检或批准让步接收的可入库数量。
- 选择仓库、库区、库位和物料批次。
- 展示已入库数量、剩余数量和库存流水。

## 7. 权限

- 采购员：创建采购订单、提交审核、登记到货。
- 采购主管：审核订单、处理超量和异常到货。
- 收货员：确认实际接收和退货数量。
- 质检员：执行检验。
- 质量主管：批准让步接收。
- 仓库员：执行正式入库。
- 管理员：配置角色权限，不因管理员身份自动跳过业务状态和数量校验。

读、写、审核、特批、检验和入库权限使用不同的权限标识。所有服务端接口独立验证权限，不能依靠前端按钮隐藏。

## 8. 错误处理与审计

系统必须拦截：

- 重复审核、重复收货和重复入库。
- 入库数量超过合格、免检或让步接收数量。
- 退货数量超过剩余可退数量。
- 累计到货静默超过采购数量。
- 已发生到货后修改采购订单关键字段。
- 普通用户执行主管特批或让步接收。
- 删除已经产生后续业务记录的单据。

所有审核、驳回、特批、收货、退货、检验、让步和入库操作写入状态日志或审计表，记录操作人、时间、前后状态、数量、原因和关联单据。已形成后续业务的记录只能冲销或关闭，不能物理删除。

## 9. 验收测试

1. 采购100件，分两次到货40件和60件，检验合格后分别入库。
2. 到货110件，100件正常处理，10件特批或退货。
3. 到货100件，接收80件、退货15件、待处理5件。
4. 无采购订单到货，登记异常，补采购订单后转为正常流程。
5. 检验不合格后全部退货。
6. 部分合格、部分不合格，合格部分入库。
7. 重复提交同一入库操作，库存只能增加一次。
8. 两名员工同时操作同一到货明细，不得超收或超入库。
9. 不同角色分别验证页面可见性和允许操作。
10. 保留所有现有业务与测试数据，不通过清理数据保证测试通过。

## 10. 后续模块关系

采购入库闭环完成后，再依次设计和实现：

1. 委外加工：工单委外工序、发出在制品、委外收货、检验、工序转移和成本。
2. 工时记录：任务开工、暂停、恢复、完工和异常工时审核。
3. 包装管理：合格SN绑定箱码、数量校验、成品入库和出货追溯。

这些模块复用本设计的权限、状态日志、幂等、数量守恒和库存流水机制。
