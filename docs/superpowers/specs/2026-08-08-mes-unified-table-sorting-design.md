# MES 统一表格排序设计

## 背景

当前系统的通用 CRUD 表已经有基础排序参数，但工单、库存、质量、设备、仓储及扩展业务表多为自定义渲染，表头没有一致的升降序交互，且刷新、搜索后排序状态不统一。用户需要在所有真正呈现记录集合的列表中按字段升序/降序查看，而不是依赖创建时间。

## 目标

- 为通用 CRUD 表和自定义业务表提供一致的表头排序按钮。
- 支持文本、数字、日期、状态、优先级等字段，空值稳定排在末尾。
- 保留各业务表原有默认顺序；用户主动排序后，刷新、分页、搜索继续使用当前排序。
- 对分页 API 使用服务端排序，对已加载数组使用前端排序。
- 不给 KPI 卡片、看板摘要或非记录型图表增加无意义的排序控件。
- 不修改或清理现有业务数据；测试数据继续保留并标注为测试。

## 方案

在 `MESUI` 中增加纯函数排序工具和表头按钮生成/状态切换能力。通用 CRUD 继续通过 `sort`、`order` 参数调用后端白名单排序，并补齐当前排序箭头、重置状态和可访问性属性。自定义页面通过同一工具保存页面级排序状态，在加载数据后排序并重新渲染；需要分页的核心生产接口增加字段白名单和 `ASC/DESC` 校验。

排序按钮使用现有蓝色工业后台视觉体系，显示字段名、方向箭头和当前激活状态；点击顺序为未排序 → 升序 → 降序 → 未排序。默认业务顺序在“未排序”状态下保持不变。

## 范围

优先覆盖工单、任务、报工、生产计划/订单、入库/出库/库存、质量检验/不良、设备台账/维修/保养、工装借用，以及供应商、客户、产品、BOM、工艺、用户、通知、异常、返工、追溯等记录列表。查询摘要、图表和看板卡片保持现状。

## 验收标准

1. 任一纳入范围的表头都能看到排序按钮，点击后行顺序和箭头状态正确。
2. 连续刷新、搜索、分页不会丢失当前排序；重置会恢复默认顺序。
3. 服务端接口拒绝未知排序字段和非法方向，不拼接不受控 SQL。
4. 空值、中文文本、数字、日期和状态字段的排序结果稳定。
5. 自动化测试、现有回归测试和浏览器验收全部通过。
