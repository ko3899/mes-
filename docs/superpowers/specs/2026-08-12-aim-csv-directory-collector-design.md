# AIM CSV 目录采集与失败重试设计

## 1. 目标与范围

在现有 AIM TCP 准入、CSV 手工上传和生产追溯能力上，增加无需机台改造的文件目录采集闭环。AIM 工控电脑仍按技术文件输出 CSV，MES 自动读取稳定文件、校验、归档并写入生产业务；失败文件隔离后允许管理员人工重试。

第一期仅支持本机或 Windows 已挂载的目录，不引入 OPC UA、MQTT、商业网关或网络文件传输协议。每个通讯端点绑定一个独立输入目录，避免双穴或多设备文件关联错误。

## 2. 方案选择

采用 MES 内置轮询采集器，默认每 2 秒扫描一次。相比依赖 Windows 文件事件，轮询对机台分段写入、网络盘抖动和服务重启更稳；相比机台 HTTP 主动上传，不要求机台厂商修改程序。

采集器作为生产启动入口管理的独立后台线程运行，与 Web 和 Socket 网关共享数据库，但每次导入使用独立连接。采集器异常不得终止 Web 服务，下一轮继续处理。

## 3. 端点配置

`iot_machine_endpoint` 增加：

- `csv_input_dir`：该机台或穴位的 CSV 输入目录；为空表示不启用目录采集。
- `csv_stable_seconds`：文件大小和修改时间保持不变的最短秒数，默认 2 秒，范围 1–60 秒。

管理端端点编辑器增加以上字段。系统校验目录为绝对路径；端点保存时不强制目录已存在，便于先配置后挂载，但健康状态显示“目录不存在”。不同启用端点不得绑定同一个规范化目录。

## 4. 文件状态与目录约定

采集器只读取 `.csv` 文件，忽略隐藏文件、临时扩展名和子目录。文件必须连续两轮满足大小、修改时间不变，且距离最后修改时间达到 `csv_stable_seconds`，才视为写完。

目录结构：

```text
机台输入目录/
  result.csv
  _processing/
  _failed/

MES归档根目录/
  YYYY/MM/DD/<文件哈希前12位>_<原文件名>
```

稳定文件先以原子移动进入 `_processing`，防止多个采集轮次重复处理。成功后原始文件已进入 MES 日期归档；失败则移动到 `_failed`，保留原始内容。

若输入目录和 MES 归档目录跨磁盘，使用“复制到临时文件、原子替换、校验哈希、删除来源”的安全退化流程。

## 5. 校验、关联与幂等

沿用现有 AIM CSV 规范：前四列必须为 `2D Barcode, Date, Time, OK(1)/NG(0)`，后续列作为动态检测值。支持 UTF-8、UTF-8-SIG 和 GBK。

报告按“端点 + SN + 当前唯一待报告 L1”关联。相同 SN、相同冻结路线步骤只允许一个待报告准入。文件哈希在端点内唯一；同一文件改名或重复复制均返回既有结果，不重复创建报工或过站记录。

成功 OK 创建待审核合格报工和 PASS 工序记录；NG 创建待审核不良报工和 FAIL 待处置记录。导入不自动过账。

## 6. 失败隔离与重试

解析失败、SN 不匹配、无待报告 L1、数据库约束失败等情况都创建 `iot_inspection_report` 失败记录，并保存：端点、可识别的 SN/检测时间/结果、原文件名、隔离路径、哈希、失败原因和重试次数。若内容无法解析，字段使用安全占位值，但原文件和失败原因必须保留。

失败报告提供管理员重试接口。重试只读取数据库记录中的服务器路径，不接受客户端传入文件路径。重试前验证路径仍位于该端点 `_failed` 或 MES 归档根目录之下。成功后更新原失败记录为 `imported`、递增重试次数并关联生产报工；失败则保留隔离文件并更新原因与次数。

管理端报告表增加“重试”操作，只对 `failed` 状态显示。手工上传失败与目录采集失败进入相同隔离/重试闭环。

## 7. 安全与权限

- 端点目录配置、手工上传和失败重试仅管理员可执行；报告与健康状态允许登录用户只读。
- 不允许浏览任意服务器目录，不提供用户输入路径的下载或重试接口。
- 文件名去除路径字符，所有目标路径经过解析并验证位于配置根目录内。
- 单文件上限 5 MB；每轮每端点最多处理 20 个文件，避免异常堆积占满服务线程。
- 文件和数据库更新遵循幂等原则；失败不得错误生成产量。

## 8. 健康状态与运维

健康接口增加：启用采集目录数、目录缺失数、待稳定文件数、隔离失败文件数和最近采集时间。管理端显示目录状态及最近错误。

生产入口统一启动和停止 CSV 采集管理器。运行时新增、停用或修改端点后，采集器下一轮自动同步，无需重启整个 Web 服务。

## 9. 测试与验收

自动化测试覆盖：

1. 未稳定文件不导入，稳定后只导入一次。
2. OK/NG 文件分别产生正确的待审核报工与 PASS/FAIL 工序记录。
3. 无效表头、SN 不匹配和无 L1 文件进入 `_failed` 并产生失败记录。
4. 修正业务条件后人工重试成功，且不新增第二条报告。
5. 同一文件改名、重复投放和服务重启不重复更新生产数据。
6. 目录缺失、跨磁盘移动失败、数据库锁和超大文件均安全失败，不影响 Web/Socket 服务。
7. 非管理员不能配置目录、上传或重试。

联调保留一套以 `TEST-AIM-` 开头的 SN、准入请求、OK/NG 报告、报工和工序记录，备注统一包含“测试”，不清理数据，供用户在管理端核对完整流程。
