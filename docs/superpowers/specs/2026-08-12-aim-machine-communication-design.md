# AIM 机台通讯中心设计

## 1. 目标与范围

在现有 MES 中增加一套面向 AIM 机台的生产通讯中心，复用现有设备台账、生产工单、冻结工艺路线、生产任务、序列号、报工与追溯数据，实现：

1. 机台扫码后向 MES 请求当前工序准入。
2. MES 在 1 秒目标时间内返回允许 `<L1>` 或拒绝 `<L3>`。
3. 机台检测完成后可靠回传 CSV 报告，MES保存原始证据和结构化检测数据。
4. 支持旧机台原始协议以及带设备、工站、穴位和请求号的增强协议。
5. 支持在线监控、拒绝原因、断线重连、幂等处理和异常重试。

第一期不采集PLC高频点位，不实现OPC UA、Modbus或运动控制，不允许MES直接控制急停、伺服、机械手和安全回路。

## 2. 采用方案

采用“兼容 V1 + 增强 V2”的独立 Socket 接入服务，并提供可靠的 HTTP 检测报告上传接口。

- V1 用于不方便改造的旧 AIM 机台：发送完整 SN，MES返回 `<L1>` 或 `<L3>`。
- V2 用于新机台和可升级机台：携带协议版本、设备、工站、穴位、请求号和SN，MES返回状态、拒绝原因及模板信息。
- 两种协议共用同一套过站校验服务和审计数据。
- CSV保留为现场原始报告格式；优先通过上传接口提交，目录扫描作为旧机台兼容方式。

## 3. 系统结构

### 3.1 Socket 接入服务

Socket 服务作为独立进程启动，与 Flask Web 服务分离，但共用同一数据库和业务服务。独立进程避免机台长连接、网络超时或异常报文阻塞管理后台。

职责：

- 监听配置的内网地址和端口。
- 根据来源IP、端口或V2报文识别设备、工站与穴位。
- 处理消息边界、字符编码、超时和最大报文长度。
- 调用统一过站校验服务。
- 返回 V1 或 V2 响应。
- 更新连接、心跳和通讯日志。

### 3.2 过站校验服务

输入为设备、工站、穴位、请求号和SN，输出为允许或拒绝、原因代码、原因文本和可选模板。

校验顺序：

1. 请求和设备配置有效。
2. 设备启用且未处于维修、停用状态。
3. 工站已绑定冻结工艺路线中的工序。
4. SN存在并关联有效工单、产品和生产任务。
5. 工单处于允许生产的状态。
6. 当前工序与SN待加工工序一致。
7. 上一工序已完成或完成合格转移。
8. SN未被报废、冻结、维修占用或判为异常。
9. 当前工序不存在已完成的重复过站记录。

任何校验失败均返回 `<L3>`；V2同时返回稳定的原因代码。数据库故障、服务超时或无法确认状态时采取失败关闭策略，禁止机台启动。

### 3.3 检测报告接收服务

V2机台通过 HTTP 上传完整CSV文件，服务端返回接收确认。旧机台继续写入约定目录，由兼容采集器在文件大小和修改时间稳定后导入。

接收流程：

1. 保存到临时文件。
2. 校验文件名、大小、编码、表头、SN、设备和请求关联。
3. 计算 SHA-256，使用设备、SN、检测时间和文件哈希防重复。
4. 原子移动到归档目录。
5. 保存报告主表和检测明细。
6. 更新SN工序、OK/NG和追溯记录。
7. 返回成功确认；失败进入隔离区并保留原因，可人工重试。

原始CSV长期作为审计证据，数据库保存结构化字段。每日XLSX只作为机台本地汇总，不作为MES唯一数据源。

## 4. 通讯协议

### 4.1 传输通则

- TCP长连接或短连接均可，默认长连接。
- UTF-8 编码；兼容配置可指定 GBK。
- 每条消息以 `\r\n` 结束，解决TCP粘包和拆包。
- 单条报文最大4096字节。
- 默认响应超时1秒，可按设备配置为500至5000毫秒。
- 同一连接默认只允许一个未完成请求。
- 空闲连接可通过 `PING/PONG` 保活。
- 不接受公网连接，只监听指定内网地址。

### 4.2 V1 兼容协议

请求：

```text
E*612201000816FB10054692B\r\n
```

允许：

```text
<L1>\r\n
```

拒绝：

```text
<L3>\r\n
```

V1通过来源IP和监听端口绑定设备、工站和穴位。同一IP存在多个穴位时使用不同端口，配置冲突时禁止启用。

### 4.3 V2 增强协议

请求：

```text
REQ|2|AIM001|LASER01|CAVITY1|000123|E*612201000816FB10054692B\r\n
```

允许：

```text
ACK|2|000123|L1|OK|LASER-T08|CCD-T16|允许加工\r\n
```

拒绝：

```text
ACK|2|000123|L3|PREVIOUS_STEP_PENDING|||上一工序尚未完成\r\n
```

字段中的竖线、回车和换行不得直接出现，模板和说明字段由服务端清洗。请求号在同一设备内唯一；重复请求返回第一次的相同判定，不重复产生过站记录。

### 4.4 NoRead 与异常

- `NoRead`记录扫码失败日志，返回 `<L3>`，不创建检测任务。
- 未知报文、超长报文、身份不匹配和频率异常立即拒绝并记录安全事件。
- 网络断开后机台自动重连；未确认准入的物料不得加工。
- 已返回L1但未收到报告的请求进入“待报告”状态，超时后报警，不自动判定OK。

## 5. 数据模型

### 5.1 `iot_machine_endpoint`

保存设备通讯配置：设备台账ID、协议版本、绑定IP、端口、工站、工序、穴位、编码、超时、心跳周期、是否启用、最后上线时间和最后错误。

### 5.2 `iot_machine_session`

保存连接会话：设备、远端地址、连接时间、最后心跳、断开时间、状态和累计请求数。

### 5.3 `iot_machine_request`

保存准入请求：请求号、设备、工站、穴位、SN、工单、任务、路线步骤、判定、原因代码、模板、请求和响应时间、耗时、协议版本及去重键。

### 5.4 `iot_inspection_report`

保存检测报告：请求、设备、SN、检测时间、OK/NG、原文件名、归档路径、文件哈希、导入状态、失败原因和重试次数。

### 5.5 `iot_inspection_value`

保存动态检测项：报告、检测点代码、检测点名称、实测值、单位、上下限和单项判定。列名不写死，支持不同功能机台的不同测量字段。

## 6. 与生产业务的关系

- 设备工站绑定到工单冻结路线步骤，而不是绑定可随时修改的基础工序。
- L1只表示“允许本次检测”，不直接增加工单完成数。
- 收到有效检测报告后创建SN工序记录。
- OK结果进入当前工序完成状态；是否自动生成和过账报工由设备配置决定，第一期默认生成待审核报工，避免机台数据绕过现有审核规则。
- NG结果进入不良和待处置状态，不计入下一工序可用合格数。
- 没有报告、重复报告、SN不一致或报告格式错误均不得更新产量。
- 字符镭雕/CCD机台可从V2响应取得镭雕模板和检测模板；模板未配置时返回L3。

## 7. 管理页面

在设备管理下新增“机台通讯”模块：

- 通讯端点配置：设备、工站、工序、穴位、IP、端口和协议。
- 在线监控：连接状态、最后心跳、当前请求、延时和最近错误。
- 准入日志：SN、L1/L3、拒绝原因、请求和响应时间。
- 检测报告：OK/NG、检测值、原始CSV、导入状态和人工重试。
- 异常中心：待报告超时、未知设备、重复报告、格式错误和连接抖动。

普通生产用户只读；设备工程师可配置和重试；系统管理员可启停监听端点。所有变更写入审计日志。

## 8. 安全、可靠性与运维

- 设备接入仅开放在OT内网，服务器使用固定内网IP，不使用PPT示例中的回环地址 `127.0.1.5`。
- V1采用IP和端口白名单；V2增加每台设备共享密钥的消息鉴权，密钥不以明文展示。
- Socket进程异常退出后由启动脚本自动重启。
- 数据库不可用时拒绝请求，不使用缓存中的旧业务状态放行。
- 通讯日志按期限清理，原始检测报告按配置归档和备份。
- 服务状态纳入现有健康检查，持续监控监听端口、连接数、L3比例、超时率和待报告数量。

## 9. 交付阶段

### 阶段一：软件模拟联调

完成数据库迁移、校验服务、V1/V2协议解析、Socket模拟器、CSV样例导入和自动化测试。无需真实机台。

### 阶段二：单台试点

选择一台AIM机台，完成固定IP、设备/工序绑定、L1/L3、OK/NG CSV、断网和重复请求测试。试运行期间不自动过账报工。

### 阶段三：正式闭环

确认数据一致后启用自动生成待审核报工、在线监控和异常告警，并推广到同类型机台。

### 阶段四：多设备扩展

根据实际需求增加视觉、称重、RFID或PLC协议适配，不改变统一准入和报告数据模型。

## 10. 验收标准

1. V1和V2正常请求均可在目标1秒内返回结果。
2. 错工序、冻结、报废、重复过站和异常设备全部返回L3，并显示明确原因。
3. 断线、拆包、粘包、乱码、超长报文和服务重启不产生错误放行。
4. 相同请求重发只产生一条业务记录并返回相同结果。
5. CSV未写完不会被导入，相同文件不会重复更新产量。
6. L1后无报告会报警，绝不自动判为OK。
7. OK/NG报告可从SN追溯到设备、工站、工单、任务、请求和原始CSV。
8. 一台双穴机台可正确区分两个穴位并行请求。
9. 模拟器、API、数据库迁移和现有回归测试全部通过。

## 11. 成本控制

第一期优先复用机台现有工控电脑、读码器、MES服务器和车间网络，不采购OPC UA网关或商业MQTT平台。软件先完成模拟器和一台机试点；只有无工控电脑、无网口或机台厂商无法实现TCP客户端时，才单独增加工控机或协议网关。

该边界将第一期成本集中在软件开发、机台厂商配合和现场联调，避免在尚未验证业务闭环前进行全厂硬件投入。
