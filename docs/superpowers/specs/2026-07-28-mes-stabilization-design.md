# MES 工厂管家稳定化设计

## 目标

在不更换现有 Flask、SQLite 和原生 JavaScript 技术栈的前提下，修复已经复现的权限、生产业务链路和管理端交互缺陷；接通已有后端能力但仍显示“页面建设中”的八个管理页面；让尚未真正对接外部系统的模块明确返回不可用状态，避免把占位响应误认为业务成功。

## 范围

本次包含：

1. 系统管理写接口的管理员权限保护。
2. 管理端动态内容的 HTML 转义。
3. 报工对任务和工单进度的事务性回写。
4. 工单、任务列表的编号和关联字段搜索。
5. 管理端缓存失效、记录对比、菜单导航、客诉删除、排序和业务状态显示修复。
6. pytest 收集配置修复。
7. 仓库、库区、库位、到货通知、库存事务、质检方案、点检项目、排班日历页面及必要 CRUD 接口。
8. AI、ERP、通知渠道、APS 和自动更新占位接口的诚实状态响应。

本次不包含：

- 用友、金蝶、SAP 或其他 ERP 的真实网络对接。
- AI 视觉模型调用、图片上传流水线或模型部署。
- 依赖设备日历、换线时间、物料齐套和有限产能约束的完整 APS 优化算法。
- 角色到菜单、按钮和数据范围的完整细粒度 RBAC 重构。

## 总体策略

修复分为四个可独立验证的批次。每批先增加会失败的回归测试，再做最小实现使其通过，最后运行完整测试集。后端行为优先使用 Flask 测试客户端验证；管理端纯函数和页面映射使用 Node 或浏览器自动化验证；端到端行为在临时 SQLite 数据库上运行，避免修改实际业务数据库。

## 一、权限和内容安全

### 系统管理权限

新增 `admin_required` 装饰器：

- 未登录返回 HTTP 401 和 `code: 401`。
- 已登录但用户名不是 `admin` 返回 HTTP 403 和 `code: 403`。
- 管理员继续执行目标函数。

用户、角色、部门、菜单和字典的新增、修改、删除接口使用 `admin_required`。读取接口暂时维持 `login_required`，保证现有管理页面和下拉选择不受影响。

现有 `permission_required` 不作为本批次授权依据，因为角色记录中的 `menu_ids` 尚未形成稳定的接口权限契约。它将被修正为拒绝没有匹配权限的请求，防止后续代码误用时默认放行，但本次不构建完整权限配置界面。

### HTML 输出

管理端增加统一 `escapeHtml(value)`：

- 普通字符串中的 `& < > " '` 转为 HTML 实体。
- 数据单元格、比较弹窗、下拉选项和动态表单默认使用转义后的文本。
- 仅由程序生成且不含业务数据的状态标签保留受控 HTML。
- 事件处理不再把完整业务对象拼入 `onclick` 字符串；行数据通过内存映射或元素 `data-id` 获取。

## 二、生产业务一致性

### 报工事务

新增后端服务函数处理一次报工：

1. 校验任务、工单和工序存在，数量为非负数，合格数量大于零。
2. 开启数据库事务。
3. 插入 `prod_report`。
4. 按任务累计所有报工的合格数和不良数，更新 `prod_task.completed_qty`。
5. 当任务累计合格数达到计划数时将任务状态设为完成；否则至少设为进行中。
6. 汇总工单下所有任务的完成数和不良数，更新 `prod_workorder`。
7. 所有任务完成时将工单设为完成；存在报工但未全部完成时设为进行中。
8. 任一步失败时回滚整个事务。

普通报工和 GPS 报工共享同一服务函数，避免两条路径产生不同业务结果。

### 扫码搜索

工单列表支持按 `order_no`、产品名称和产品编码模糊搜索；任务列表支持按 `task_no`、关联工单号和工序名称模糊搜索。无匹配结果必须返回空列表，采集端不得回退到最新记录。

## 三、管理端交互

### API 缓存

GET 请求保留五秒缓存。任何成功的 POST 写操作后清空缓存，再触发列表刷新。失败响应不清缓存。导入成功后同样清空缓存。

### 记录对比

通用 CRUD 列表在当前页面保存 `id -> row` 映射。勾选两条记录后直接从映射读取完整数据进行比较，不再发送 `size=1` 的错误请求。翻页或重新加载时清理已不存在的选择项。

### 菜单和页面映射

顶层菜单使用自己的 `k` 作为 `data-page`，`home` 只表示该项不属于折叠菜单。数据看板进入 `analytics/dashboard`，消息通知进入 `notifications`。

以下页面加入明确的渲染映射：

- `warehouse/list`
- `warehouse/area`
- `warehouse/location`
- `warehouse/arrival`
- `warehouse/transaction`
- `qm/template`
- `eqp/check-project`
- `sched/calendar`

页面沿用现有卡片、表格、分页和模态框样式，不引入新前端框架。

### 其他交互

- 增加 `/api/svc/complaint/delete`。
- 后端排序参数不区分大小写并统一为大写。
- 字段配置中的状态枚举优先于通用“启用/禁用”文案。
- 新增 `pytest.ini`，只收集真正的 pytest 测试模块；截图和外部服务脚本继续保留为手动工具，不在 pytest 导入阶段执行。

## 四、八个页面的后端契约

已有列表、添加和更新接口继续使用；缺失的接口补齐：

- 库区：更新、删除。
- 库位：更新、删除。
- 到货通知：删除。
- 库存事务：只允许新增和查询，不提供修改与删除，以保留审计记录。
- 质检方案：删除。
- 排班日历：更新、删除。
- 仓库和点检项目沿用现有完整 CRUD。

所有写接口使用 `login_required`；系统配置类接口仍按第一部分的管理员规则保护。关联下拉数据通过现有仓库、供应商、产品、设备、班组和排班计划列表接口获取。

## 五、占位模块的行为

### AI

`/api/ai/config` 从数据库读取保存过的配置。未配置并启用提供商时，`/api/ai/inspect` 返回 HTTP 503、`code: 503` 和清晰错误信息，不返回 PASS。仅保存配置不代表已经具备模型调用能力；在没有实现适配器时仍返回不可用。

### ERP

所有同步接口在没有对应适配器实现时返回 HTTP 501、`code: 501`。配置保存接口继续可用，但同步接口不再返回成功文案，也不回显密钥。

### APS

`/api/aps/schedule` 改为排程预览：

- 校验 ISO 日期且开始日期不晚于结束日期。
- 返回 `mode: preview`。
- 明确不修改数据库、不把工单标记为已排程。
- 详情项使用“待排程”状态，并包含输入日期范围。

完整排程持久化留待确定资源、班次和约束规则后实施。

### 通知渠道和自动更新

通知渠道测试在没有具体发送适配器时返回 HTTP 501。自动更新下载接口返回 HTTP 501，并提供人工下载地址字段，不再以 `code: 0` 表示已经下载。

## 错误处理

- 认证、授权、验证失败使用对应的 401、403、400 HTTP 状态。
- 外部能力未实现使用 501，已实现但配置缺失使用 503。
- 前端 API 工具先检查 HTTP 和内容类型；非 JSON 响应转成统一错误对象，不再静默返回 `null`。
- 写操作失败时保留当前表单或页面，并显示后端消息。
- 报工、删除和导入必须以服务器成功响应为准更新页面。

## 数据兼容

不删除现有表或字段，不修改已有记录格式。新增代码基于当前 SQLite 表结构工作。所有数据库变更均使用现有初始化机制和幂等 `ALTER TABLE`/`CREATE TABLE IF NOT EXISTS` 模式；本次设计预计不需要新表。

## 测试设计

### 后端回归测试

- 普通用户访问系统管理写接口得到 403。
- 管理员仍可执行系统管理写操作。
- 报工后任务、工单数量和状态正确；失败时事务回滚。
- 不存在的工单号和任务号搜索返回空列表。
- 客诉删除成功。
- 小写 `asc` 和 `desc` 得到不同顺序。
- 八个页面所需 CRUD 接口覆盖成功和缺失 ID。
- AI、ERP、通知和更新占位接口返回 501/503。
- APS 无效日期返回 400，有效日期返回预览且数据库不变。

### 前端回归测试

- 业务文本按文本显示，HTML 标签不进入 DOM。
- POST 成功后缓存失效。
- 两条记录比较不再停留在加载状态。
- 数据看板和消息通知菜单进入正确页面。
- 八个菜单不再出现“页面建设中”。
- 业务状态使用字段配置中的文案。

### 完整验证

1. `python -m pytest -q`
2. Python 源码编译检查。
3. 所有管理端 JavaScript 语法检查。
4. 在临时数据库上进行管理端和采集端浏览器冒烟测试。
5. 确认实际业务数据库和 Git 之外的运行文件未被测试修改。

## 完成标准

- 新增回归测试先失败、实现后通过。
- 完整 pytest 命令可以成功收集并全部通过。
- 已复现的权限、报工、扫码、缓存、比较、导航、删除、排序、状态和 HTML 注入问题均无法再次复现。
- 八个指定菜单展示可操作页面。
- 未实现的外部集成不再返回成功结果。
- Git 工作树中只包含本次规格、测试和实现相关修改。
