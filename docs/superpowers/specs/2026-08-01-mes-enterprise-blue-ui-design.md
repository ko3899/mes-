# MES 管理后台「精致企业蓝」UI 重构设计

日期：2026-08-01  
状态：待用户最终审阅

## 1. 目标与边界

本次重构面向每天长时间使用系统的生产主管、计划员、仓库、质量、设备及系统管理员。目标是把当前视觉层级薄弱、组件样式不完整的后台，重构为清晰、克制、可靠的工业企业级工作台。

本次仅调整管理后台的 HTML、CSS 和必要的前端渲染结构，不修改后端接口、数据库结构、权限模型或业务语义。现有页面路由、元素 ID、全局交互入口和已完成的安全修复必须保留。不存在真实能力的集成项不得用视觉包装成“可用”。

## 2. 设计方向

采用已确认的 B 方案「精致企业蓝」：深海军蓝导航框架承载稳定感，浅灰蓝工作区保证信息密度，白色内容卡片承载数据，亮蓝仅用于当前状态与关键动作。整体避免廉价渐变、大面积高饱和色、夸张悬浮位移和装饰性阴影。

可记忆特征是“生产指挥台”：侧栏像设备控制面板一样紧凑稳定，工作区以清晰的指标、趋势、预警和待办构成操作节奏。

## 3. 视觉系统

### 3.1 色彩

- 导航底色：`#0B1F3A`，二级层次使用 `#102A4C`。
- 主操作色：`#2563EB`；悬停和焦点使用更深蓝色。
- 工作区底色：`#F3F6FA`；卡片底色：`#FFFFFF`。
- 主文字：`#172033`；次文字：`#667085`；边框：`#E2E8F0`。
- 成功、警告、危险、信息分别使用克制的绿、琥珀、红、蓝，并同时提供文字或图标语义，不只依赖颜色。
- 深色主题复用同一语义变量，内容背景、边框、文字和图表配色成套切换。

### 3.2 字体与尺度

中文正文优先使用 `"Microsoft YaHei UI"`、`"PingFang SC"`、`"Noto Sans SC"`，数字与英文使用系统内清晰的无衬线字体。标题通过字重、间距和字号建立层级，不引入运行时外部字体依赖。

基础圆角为 8px，核心卡片为 12px；间距遵循 4px 基准；按钮和输入框高度统一为 36px 或 40px。阴影只用于浮层和需要明确层级的卡片，常规分区以边框完成。

### 3.3 动效

只保留 120–200ms 的颜色、边框、透明度和轻微位移动效。页面首次进入可做一次克制的分组淡入；必须遵循 `prefers-reduced-motion`。表格行、菜单和按钮不得使用夸张缩放或跳动。

## 4. 信息架构与应用骨架

桌面端由固定深色侧栏、顶部栏和可滚动内容区构成：

- 侧栏顶部为产品标识、MES 名称和“工厂管家”副标题。
- 菜单按生产、仓储、质量、设备、报表、系统等业务域分组，支持折叠展开；当前页面使用左侧强调线、图标底色和文字颜色共同标识。
- 侧栏底部承载当前用户、角色和退出入口。
- 顶部栏显示面包屑/页面标题、全局搜索入口、消息、主题切换和用户菜单。
- 内容区使用统一最大间距与响应式栅格；批量操作条在有选择项时贴近内容下方出现。

现有路由、菜单权限过滤和页面加载方式保持不变；重构仅为现有菜单数据增加语义类名与必要包装。

## 5. 核心页面

### 5.1 登录页

采用企业级左右分栏：左侧深蓝品牌区展示 MES 的生产协同价值、三项能力摘要和低干扰的工业网格纹理；右侧为白色登录区，突出账号、密码、验证码/提示与登录按钮。窄屏下品牌区压缩为顶部品牌条，表单保持单列。

保留现有登录接口、字段 ID、错误提示和提交逻辑。密码可见性、焦点态、键盘提交和错误态需要清楚可见。

### 5.2 工作台

工作台按照“今天发生了什么 → 趋势如何 → 哪里需要处理”的顺序组织：

1. 欢迎区展示日期、班次/状态摘要和首要快捷入口。
2. 第一行核心指标卡展示计划、完成、在制、良率、设备状态等现有数据；卡片突出数字、变化和单位，而不是装饰图标。
3. 第二层放置产量趋势、订单/工单状态和设备/质量概览图表。
4. 第三层放置预警、待处理事项和快捷操作，危险项可直接定位到对应业务页。

ECharts 容器、数据接口和图表更新逻辑保持不变，只统一容器、标题、图例和主题颜色。

### 5.3 列表与业务页

- 页面头统一为标题、简述、主操作按钮。
- 筛选区使用紧凑工具栏，在窄屏自动换行；搜索、选择器、日期和重置动作风格一致。
- 表格头使用浅灰蓝底与清晰分隔，不使用渐变；行悬停只改变背景色。
- 数值右对齐，名称左对齐，操作列固定视觉节奏；空数据、加载和错误状态有一致样式。
- 分页展示总数、页码和每页数量，移动端允许简化。
- 状态标签使用淡色底、深色文字和圆点/图标，不使用高饱和胶囊堆叠。

### 5.4 表单、弹窗与反馈

- 表单按标签、说明、控件、错误提示四层组织，必填标记与禁用态一致。
- 弹窗采用统一标题区、滚动内容区和底部操作区；关闭、取消、确认顺序稳定。
- 删除等危险操作使用确认语义与危险色；保存中阻止重复提交。
- Toast、加载、空状态、无权限和网络错误形成统一反馈体系。
- 现有弹窗函数、表单处理器和 DOM ID 不改名，以避免破坏业务交互。

## 6. 响应式与可访问性

- 大于 1200px：完整侧栏与多列工作台。
- 768–1199px：侧栏可收起为图标栏，卡片减少列数。
- 小于 768px：侧栏变为带遮罩的抽屉，顶栏简化，表格允许横向滚动，弹窗接近全屏。
- 所有交互元素提供可见的 `:focus-visible`；点击区域至少 40px；弹窗和抽屉具备明确层级。
- 颜色对比以 WCAG AA 为目标，状态同时使用文本/图形表达。

## 7. 实现策略

1. 先用自动化测试锁定应用骨架、主题变量、关键组件类和既有 DOM 契约，并确认测试因新设计尚未实现而失败。
2. 重建 `admin/static/css/style.css` 的设计令牌和基础布局，再实现登录、侧栏、顶栏、工作台及共享组件。
3. 只在必要处调整 `admin/index.html`、`admin/static/js/menu.js` 和 `admin/static/js/pages/home.js` 的语义包装，保留既有 ID、事件和数据流。
4. 每批实现后运行相关 Node/Python 测试及静态检查，最后运行完整回归。
5. 在真实本地服务中完成桌面与移动视口的登录、菜单、主题、表格、弹窗和快捷操作验收，检查控制台错误并保存截图。

## 8. 验收标准

- 登录页、应用骨架、工作台和所有共享业务组件呈现统一的 B 方案视觉语言。
- 侧栏展开/收起、移动抽屉、菜单分组、主题切换、弹窗、表单、分页和批量操作均可交互。
- 现有后端 API、数据库和业务结果没有变化；既有自动化测试全部通过。
- 新增 UI 契约测试先红后绿，浏览器验收无阻断性控制台错误。
- 1366×768、1920×1080、768×1024 和 390×844 视口无明显遮挡、溢出或不可操作区域。
- 深色主题不是简单反色，文字、边框、图表和浮层在深色背景下仍清楚可读。

## 9. 非目标

- 不新增后端业务模块或第三方集成。
- 不更换前端框架，不引入大型 UI 组件库。
- 不重写现有 API 客户端和权限系统。
- 不以视觉重构为由清理无关业务代码。
