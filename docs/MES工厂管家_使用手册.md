# MES 工厂管家使用手册

版本：2026-08

## 1. 系统是做什么的

MES 工厂管家用于把“基础资料 → 生产计划 → 工单执行 → 现场报工 → 质量检验 → 入库/出库 → 报表看板”串成一条可追溯流程。

系统有三个入口：

| 入口 | 地址 | 主要用户 | 作用 |
| --- | --- | --- | --- |
| 采集客户端 | [http://127.0.0.1:8080/](http://127.0.0.1:8080/) | 操作员、检验员、仓管员 | 扫码、任务、报工、质检、库存/工具 |
| PC 管理后台 | [http://127.0.0.1:8080/admin](http://127.0.0.1:8080/admin) | 计划员、生产主管、质量、设备、管理员 | 主数据、工单、库存、质量、设备、报表 |
| 生产指挥看板 | [http://127.0.0.1:8080/kanban](http://127.0.0.1:8080/kanban) | 车间主管、管理层 | 查看实时工单、产出、设备和质量状态 |

默认账号：`admin` / `admin123`。首次登录后应立即修改密码。

## 2. 启动与停止

### 推荐启动方式：统一服务

在项目根目录执行：

```powershell
python start_app.py
```

也可以执行：

```powershell
python backend/app.py
```

启动后使用 8080 端口，管理后台、采集客户端和看板共用同一套登录会话与数据库。

停止：在运行窗口按 `Ctrl+C`。

### Windows 一键启动

双击 `Start All.bat` 会启动：

- 采集端：`8080`
- 独立管理端：`8081/admin`

这是兼容旧部署的方式。日常开发和演示建议使用统一服务，避免同时启动两个后端进程造成端口、会话或数据初始化混淆。

### 启动检查

浏览器依次打开：

1. `/admin`，确认能登录管理后台；
2. `/`，确认采集端显示“在线”；
3. `/kanban`，确认看板能显示“数据在线”。

如果页面打不开，先确认 Python 进程是否仍在运行，以及 8080 端口是否被其他程序占用。

## 3. 总体业务流程

```text
组织/用户/权限
      ↓
车间、工序、产品、BOM、工艺路线
      ↓
销售订单/生产计划
      ↓
生产工单
      ↓
工序任务分配
      ↓
现场扫码执行与报工
      ├────────→ 过程检验/首件检验
      ├────────→ 不良处理/返工
      └────────→ 物料领用、工具借用、设备记录
      ↓
合格品入库 / 包装 / 出货检验
      ↓
生产报表、质量统计、设备状态、生产看板
```

最小可运行流程是：

1. 建立车间、工序、产品和单位；
2. 建立产品 BOM 或物料关系；
3. 创建生产工单并填写计划数量；
4. 为工单建立工序任务；
5. 操作员在采集端打开“任务”或扫码进入工单；
6. 在“报工”录入合格数和不良数；
7. 质量人员在“质检”登记结果；
8. 仓库办理入库/出库；
9. 主管在工作台、报表和 `/kanban` 查看进度。

## 4. PC 管理后台怎么用

### 4.1 工作台 / 数据看板

入口：管理后台首页、数据看板。

查看今日核心指标、进行中工单、设备运行率、库存和质量提醒。这里主要是“读数据”，不会替代工单、报工或质检操作。

影响范围：

- 工单数量和状态来自生产工单；
- 产出和合格率来自报工记录；
- 设备运行率来自设备台账状态；
- 质量提醒来自待检和不良记录；
- 首页快捷按钮会跳转到对应业务模块。

### 4.2 基础数据

建议最先维护以下内容：

| 模块 | 用途 | 会影响 |
| --- | --- | --- |
| 车间设置 | 定义生产区域 | 工序、工单、设备、看板车间统计 |
| 工序管理 | 定义生产步骤 | 工艺路线、任务、报工、过程检验 |
| 产品定义 | 定义产品编码、单位、规格 | 工单、库存、报表、扫码识别 |
| 物料清单 BOM | 定义产品用料 | 生产领料、物料追溯、库存需求 |
| 工艺路线 | 定义产品经过哪些工序 | 任务顺序、过站、报工校验 |
| 不良品项 | 定义缺陷类型 | 报工不良、质量处理、统计 TOP |
| 供应商/客户 | 维护往来对象 | 采购入库、销售订单、出货 |

维护原则：先编码，再业务。产品编码、工序编码和工单号一旦投入使用，不要随意修改；停用优先于删除。

### 4.3 生产管理

典型操作顺序：

1. 销售订单：记录客户需求（如果启用销售流程）；
2. 生产计划：确定数量、交期和优先级；
3. 工单管理：生成实际生产任务；
4. 任务管理：把工单拆到具体工序、人员或工作站；
5. 报工管理：汇总现场完成数和不良数；
6. 工序转移、生产领料、序列号、包装：按工厂实际流程启用。

影响关系：

- 修改工单计划数量，会影响任务完成率、看板进度和生产报表；
- 修改工单状态，会影响“进行中工单”列表；
- 报工会增加合格/不良数量，并更新任务和工单完成进度；
- 重复提交同一个客户端操作号不会重复增加产量；
- 工序路线或工序状态变化，可能导致后续任务无法创建或扫码校验失败。

### 4.4 质量管理

主要模块：来料检验、过程检验、首件检验、出货检验、不良品处理、8D、CAPA、控制计划、质检方案。

推荐流程：

1. 来料到货后创建来料检验；
2. 生产过程中按工序登记过程检验或首件检验；
3. 发现不良后登记缺陷、数量和处理方式；
4. 需要时创建返工、让步接收或报废记录；
5. 出货前完成出货检验；
6. 在质量统计和 SPC 中分析趋势。

影响范围：质量记录会影响看板“质量待处理”、不良数量、合格率、返工记录和追溯查询。质量检验不会自动替代报工；报工数量仍由生产报工产生。

### 4.5 库存管理

主要模块：入库单、出库单、库存余额、仓库、库区、库位、到货通知、库存事务、线边仓。

推荐流程：

1. 先配置仓库、库区和库位；
2. 物料到货后建立到货通知或入库单；
3. 生产领料通过出库/领料记录关联工单；
4. 完工后按业务规则办理成品入库；
5. 通过库存余额和库存事务核对账实。

影响范围：库存事务改变库存余额；产品编码、单位和批次错误会同时影响领料、入库、追溯和库存报表。删除库存基础资料前，应先确认没有业务单据引用。

### 4.6 设备、工具与现场

设备模块维护设备台账、维修单、保养计划、保养记录和点检项目；工具模块维护工具台账、借用和归还；现场模块包含工作站、安灯、返工报废和阶段记录。

影响范围：

- 设备状态影响首页 OEE/设备运行率和生产看板；
- 维修、保养逾期会形成首页提醒；
- 工具借用会生成真实借用记录，不等同于物料出库；
- 安灯和异常记录用于现场响应，不会自动修改工单完成数；
- 返工/报废记录会进入质量与生产追溯。

## 5. 采集客户端操作手册

采集端适合手机、平板和现场工位机。底部导航包括：首页、扫码、任务、报工、质检、库存。

### 5.1 首页

显示当前用户、网络状态、待同步离线记录和快捷入口。首页指标来自当前账号可见的任务和报工数据。

### 5.2 扫码

支持摄像头扫码，也支持手动输入编码。可识别工单号、任务号、产品或条码。

操作步骤：

1. 点击“扫码”；
2. 允许浏览器使用摄像头（首次使用时）；
3. 对准条码，或切换到手动输入；
4. 根据识别结果进入任务、报工或产品信息；
5. 如果提示“未找到”，先检查条码是否属于当前系统，以及账号是否有权限。

在不支持摄像头的浏览器中，手动输入仍可使用。扫码本身只负责识别和跳转，不会自动产生报工。

### 5.3 任务

查看当前用户的待执行和进行中任务。进入任务后可查看工单、产品、工序、计划数量和已完成数量。

影响范围：任务状态由生产后台创建/更新；报工完成后，任务完成数量和状态会更新。

### 5.4 报工

录入合格数量、不良数量、备注，必要时填写设备、工位或 GPS 信息。

操作步骤：

1. 选择任务或通过扫码带入任务；
2. 填写合格数和不良数；
3. 检查数量不能超过任务/工单可报数量；
4. 提交并等待“报工成功”；
5. 在报工记录或首页确认结果。

断网时，客户端会将可重试的报工放入当前用户的离线队列；恢复网络后自动按顺序同步。业务校验失败的记录不会无限重试，需要打开记录修正。

### 5.5 质检

查看待处理检验、登记检验结果和缺陷信息。质检结果会影响质量待处理数量、质量统计和看板告警。

### 5.6 库存 / 工具

库存页用于按产品搜索实时结存；工具借用填写工具 ID 和数量后提交，会生成工具借用记录。归还和台账维护在 PC 管理后台完成。

## 6. 生产看板怎么读

入口：[http://127.0.0.1:8080/kanban](http://127.0.0.1:8080/kanban)。看板每 30 秒自动刷新，也支持“立即刷新”和 F11 全屏。

| 看板区域 | 数据来源 | 什么时候会变化 |
| --- | --- | --- |
| 今日合格产出 | 当日合格报工 | 新增/修正报工 |
| 今日不良数量 | 当日不良报工 | 新增不良报工 |
| 今日合格率 | 合格数 ÷（合格数 + 不良数） | 报工变化 |
| 活跃工单 | 状态为待开始/进行中的工单 | 工单状态或新增工单 |
| 设备运行率 | 设备台账状态 | 设备状态变更 |
| 进行中工单表 | 工单、产品、计划/完成数量 | 工单或报工变化 |
| 车间今日产出 | 车间关联工序的合格报工 | 报工变化 |
| 质量待处理 | 待检数量 + 当日不良数量 | 检验或不良处理变化 |

网络短暂中断时，看板会保留最近一次成功快照并标记过期；初次加载失败会显示登录或错误提示，不会伪造为“正常数据”。

## 7. 模块影响关系速查

| 修改位置 | 直接影响 | 不会自动影响 |
| --- | --- | --- |
| 产品定义 | 工单选项、库存查询、扫码识别、产品报表 | 已提交报工历史 |
| 工序/工艺路线 | 任务生成、扫码校验、过站顺序 | 已完成的历史任务 |
| 工单计划数量 | 任务计划、完成率、看板进度 | 库存余额 |
| 报工 | 工单完成数、任务状态、合格率、看板产出 | 物料库存（除非另有领料/入库动作） |
| 质检结果 | 质量告警、不良统计、追溯 | 工单完成数量 |
| 设备状态 | OEE、设备运行率、看板设备图 | 工单数量 |
| 入库/出库/领料 | 库存余额、库存事务、批次追溯 | 工单完成数量 |
| 用户/角色/权限 | 可见菜单和可执行操作 | 已有业务数据 |

## 8. 常见问题

### 页面能打开但一直提示未登录

确认访问的是同一个端口；统一服务请使用 8080。清理浏览器站点 Cookie 后重新登录。若使用 8081 独立管理端，不要把 8081 的登录状态当成 8080 的登录状态。

### 扫码没有反应

检查浏览器摄像头权限、光线和条码内容；也可以直接使用手动输入。摄像头不支持时不影响任务、报工和质检的手动流程。

### 报工提交失败

先确认任务仍然有效、数量未超计划、合格数和不良数为非负数。若是网络问题，记录会进入离线队列；若是业务校验失败，需要修正后重新提交。

### 看板数字没有更新

点击“立即刷新”，确认页面显示“数据在线”。看板统计按服务器当天日期计算；跨天后昨日数据不会继续计入今日指标。

### 数据不一致

按“工单 → 任务 → 报工 → 质检/库存事务”的顺序核对，不要只看首页数字。优先检查是否选择了错误产品、工序、工单或日期。

## 9. 数据和备份建议

- SQLite 数据库位于项目数据目录，生产环境应定期备份数据库文件和 `backups/` 目录。
- 上线前先建立管理员、角色、部门和基础编码，再导入业务数据。
- 生产中尽量使用“停用”而不是直接删除基础资料。
- 修改工单、报工和库存前先确认单号、产品、数量和日期。
- 需要升级程序时，先停止服务、备份数据库，再启动新版本并检查首页、采集端和看板。

## 10. 管理员日常检查清单

每天开始生产前：

- 检查服务和数据库是否正常；
- 检查当天工单、任务和设备状态；
- 检查待检、逾期保养和库存预警；
- 用采集端测试一次扫码或手动报工入口。

每天结束生产后：

- 核对报工合格/不良数量；
- 处理待检和不良记录；
- 核对入库、出库和工具借用；
- 查看生产报表和看板是否存在异常；
- 执行数据库备份。
## 列表排序

工单、任务、报工、库存、质量、设备、工装、主数据及系统记录列表的表头都支持排序。点击字段名右侧的“↕”按钮：第一次为升序（ASC），第二次为降序（DESC），第三次恢复该页面默认顺序。排序会在刷新、搜索和分页后保留；点击“重置”会清除搜索并恢复默认顺序。数字、日期和中文文本按对应类型比较，空值统一排在末尾。看板指标卡、统计图表和摘要表不提供排序，因为它们不是可操作的记录列表。

### 手工调整记录位置

记录型列表第一列显示的是可调整的“排列 ID”。真实主键在页面中隐藏，只用于数据库关联，调整排列时不会修改真实主键，也不会破坏工单、任务、报工等业务关系。

点击操作区的“↑”或“↓”可移动一位，同时交换两条记录的排列 ID。例如排列 ID 8 上移后变成 7，原来排列 ID 7 的记录变成 8。点击“移到”后输入目标排列 ID，可直接把第 9 条移动到第 6 条，其间记录依次后移。排列结果保存在数据库中，刷新、重新登录或换电脑后仍然有效，各模块互不影响。分页和搜索状态下输入的仍是全量数据的排列 ID。若已经点击表头按某个字段升序或降序，手工移动会暂时禁用；请第三次点击该表头恢复默认顺序，再调整记录位置。
